## 1. 项目目标与范围

完成面向学生、教授和教务员的选课系统，交付可运行程序、可复现的验证证据及课程要求的文档。采用迭代增量开发；原周计划保留，第 4 节记录当前执行冲刺，文档随实现同步。

计划覆盖以下业务范围，详细验收条件在需求分析与用户故事中补齐：

| 领域 | 交付范围 |
| --- | --- |
| 身份与权限 | 三类角色登录；学生数据隔离；教授仅操作自己负责的班次；教务员维护人员信息 |
| 学生选课 | 浏览目录，保存／提交／更新／删除；首次 4+2，后续 1—4 主选／0—2 备选；版本竞争、加退选 |
| 选课校验 | 班次容量上限 10 人；先修条件、时间冲突、开放状态检查；提交前的额满提示 |
| 教授业务 | 选择与取消授课班次、授课冲突检查、查看名册、录入及修改成绩 |
| 教务业务 | 人员状态影响预览确认、xlsx 人员／历史成绩／资格导入、窗口设定；关闭、单轮调剂与取消、P1 关闭后补选 |
| 外部系统 | 独立只读 HTTP 目录、变更复查通知；计费模拟、版本替换、每 60 秒重试与重启恢复；教师接受模拟仍待确认 |
| 成绩查询 | 学生查看本人上一已完成学期的成绩单 |

课程信息的外部维护系统、实际收费处理不属于本系统实现范围。未经需求评审，不自行增加支付、即时聊天等扩展功能。

保留题目性能与可靠性要求：中央数据库 2000 并发用户、本地服务器 500 并发用户、旧目录访问延迟不超过 10 秒、80% 交易在 2 分钟内完成、全天候可用且停机不超过 10%。测试计划须明确环境、负载模型及可用性统计窗口；不能将短时演示等同于长期可靠性验证。任何调整均记录确认依据。

- 沿用 [迭代流程](ITERATION_GUIDE.md)、[Git 工作流](GIT_WORKFLOW.md)、[测试策略](TESTING.md) 和 [完成定义](../CONTRIBUTING.md)。

- 缺陷记录复现步骤、影响范围、负责人及验证结果。数据损坏、越权、核心流程无法完成的缺陷阻止交付；其他未修问题明确记录并评审。
- 需求变更说明原因、受影响模块、测试与日期，由倪成锦组织评审；课程要求口径变化保留教师确认记录。同步更新 backlog、设计与测试。
- 迭代评审通过后再按规范发布；本地可运行、CI 通过和教师验收分别记录，不互相替代。
