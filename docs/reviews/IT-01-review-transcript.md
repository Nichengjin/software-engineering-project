\[倪成锦]: 第二个是技术选型。9 月 22 号定的，记在 ADR-001 里了。这个我念一下重点：前端是 React 加 TypeScript 加 Vite，路由用 TanStack Router；后端是 Hono；数据库是 PostgreSQL，ORM 用 Prisma；建模工具用 StarUML。

\[冯海洋]: 那我问一个可能有点笨的问题啊，课件里写的是 Vue 加 Spring Boot 或者 Vue 加 Django 那种，我们一个都没用，这个要紧吗？

\[倪成锦]: 课件那段是「可采用」，不是必须。选 React 和 Hono 主要是两个原因：一是我们几个本来就熟 TS，前后端一套类型，接口字段不用两边各写一遍；二是它是一个 npm 仓库里放几个包，本地起来不用装两个语言的运行时。Spring Boot 得再装 JDK 和 Maven，我们这几台机器环境本来就乱。

\[马喆]: 那数据库呢？课件里列的 MySQL、SQL Server、DB2、SQLite，我们用的是 Postgres。

\[倪成锦]: 同一个道理，Postgres 本地好装，而且它有几个我们后面要用的东西，一会儿设计阶段会说。这个也写进 ADR 的理由里了。

\[范昭]: 建模工具那个我想说一句。课件列的是 Rational Rose、Rational Software Architect、Enterprise Architect、Visio、PowerDesigner，StarUML 不在里面。

\[倪成锦]: 嗯，这个是有点风险。

\[范昭]: 我那台是 Mac，上面几个要么装不了要么要授权。StarUML 是跨平台的，而且它导出的图能进仓库，跟代码一起版本管理。

\[倪成锦]: 那我们在 ADR 里加一句，说明 StarUML 不在课件清单里，选它的原因是什么。评阅人看到清单对不上，至少有个解释。这也算今天的一条修改意见。

\[范昭]: 那这两个的边界得定清楚，比如目录系统里哪些字段是我们能读的，哪些不读；计费系统收什么、回什么。不然前后端对接的时候又要扯一轮。
