\[倪成锦]: 开始吧。今天是 IT-03 的评审，这轮目标是从学生选课一直走到关闭计费、成绩录入查询，整条链路能演示。今天时间会长一点，我打算把主链路从头走一遍，中间随时打断。

\[倪成锦]: 顺序：学生端保存和提交，教授端授课和成绩，教务端人员和导入，然后是关闭、调剂、计费，最后是补选。冯海伦的独立验收单独放最后讲。

\[倪成锦]: 浩宇，从你那儿开始。

\[浩宇]: 好。我现在用的是从来没有提交过的学生账号。我先保存一份课表，四个主选两个备选。

\[浩宇]: 保存完了。这里注意一下——保存之后，这个人还是没注册的。我切到教授那边看名册，名册里没有他。

\[马喆]: 对，我这边看不到。

\[浩宇]: 然后我正式提交。……提交成功。现在再回名册。

\[浩宇]: 有了，四门课各多了一个人。备选那两个没占名额。

\[倪成锦]: 停一下。你刚才那次提交，是整份一起生效的吗？

\[浩宇]: 是。前面我试过一个失败的例子。我把其中一门换成一个和他别的课时间冲突的班，提交就整份失败。失败之后他原来那四门的注册还在。

\[倪成锦]: 这个「整份失败，原注册保持」，是这轮才做对的还是上轮就有？

\[倪成锦]: 我自己回答吧，上轮就有，但那会儿只有一个用例覆盖。这轮冯海伦补了六种失败原因的，包括先修的三种情况。

\[冯海伦]: 对，先修那个我分了「及格加不及格」「及格加缺成绩」「及格加一个 I」，I 不算及格。

\[马喆]: 那加退选呢？加退选期结束以后还能改吗？

\[浩宇]: 不能。窗口关了以后按钮点了会报「不在选课窗口内」。

\[倪成锦]: 服务端也拒，不是只靠界面。

\[浩宇]: 对，这个我在接口上也试了。

\[浩宇]: 还有一个删除课表。删了之后课表清空、注册释放，而且他那个「首次提交时间」也一起清掉。后面他要是重新选，就按第一次提交处理，得重新 4+2。

\[马喆]: 那这个清掉以后，调剂的时候他排在哪？

\[浩宇]: 排在新时间上。

\[马喆]: 哦，就是如果他删过，他后面的优势就没了。

\[浩宇]: 对。

\[倪成锦]: 这条是需求里专门定的，因为不确定的话实现起来容易漏。好，马喆。

\[马喆]: 教授端。这是选择授课的页面。我先把一门课取消，再加一门有时间的……这门跟我剩下的冲突。

\[马喆]: 确认的时候它报冲突了，把我保留的那两门原样列出来，新增的没有进去。

\[浩宇]: 那如果先取消再新增呢？

\[马喆]: 也是整份，一起生效一起不生效。我试过一次，中途故意让它失败，结果取消也没生效。

\[倪成锦]: 这个我们上轮专门改过。原来会出现「先撤了旧的，新增失败」的中间状态。

\[马喆]: 然后是成绩录入。这个班十个人，我填六种成绩，一个人留空，一个人把原来的 B 改成 D。

\[马喆]: 保存。……留空的那个还是原来的分，不是被清掉。改的那个变成 D 了。

\[冯海洋]: 那如果填个非法值呢？

\[马喆]: 我填过「Z」。它单独报了那一格，其他的照常存进去。

\[倪成锦]: 这个是按格子分别处理的，一个格子坏了不连坐。这条也是需求里写死的例外。

\[冯海洋]: 我插一个。上线以前的学期，教授能录吗？

\[马喆]: 不能。我拿了一个上线以前的学期试，页面上根本没有可选的班次。是教务导入。

\[浩宇]: 学生这边查成绩单我也做了。只能查自己上一个已经完成的学期，不会混到更早的或者没完成的那个学期。

\[冯海洋]: 那如果那个学期他就没成绩呢？

\[浩宇]: 会明确说「没有该学期成绩」，不是空白页，也不是拿更早的学期顶上。

\[倪成锦]: 好。冯海洋，教务这块。

\[冯海洋]: 我这边两块。人员维护我已经演示过了，上轮是导入，这轮补的是状态。

\[冯海洋]: 这个教授我要改成离职。改之前它会先列出来：这个人在没关闭的学期里带了两门课，关了的那学期还有成绩。

\[冯海洋]: 确认以后，他登不进去了，那两门课变成没有教授，历史成绩还在。

\[倪成锦]: 列表里有没有把「会影响什么」写清楚？

\[冯海洋]: 写了，逐条列的。取消的话什么都不动。

\[冯海洋]: 学生那边一样。改休学，他会把没关闭学期的课表退掉；改毕业，也一样；历史成绩保留，还能登录查，但不能选课。

\[马喆]: 那如果他正好在别人抢他那个名额的时刻被改成休学呢？

\[冯海洋]: 这个是竞态吧？

\[倪成锦]: 是。这个我们改过一版：关闭过程中和删学生之间有个窗口，会让两个操作打架。现在是串起来的。

\[冯海伦]: 那条我验了，注入失败以后整体回滚，不会出现「状态改了但课表没退」。

\[倪成锦]: 好。现在是关闭选课这段。这段最长，我来讲，冯海洋操作界面。

\[倪成锦]: 现在这个学期有一批学生，有几个班的人数不一样，有 0 人的、1 人的、2 人的、3 人的，还有一个没有教授但是满了的。

\[倪成锦]: 教务按下关闭。……停一下，这个截图是刚才那个时刻的，我放大一下。

\[倪成锦]: 关闭的结果分几块：取消掉的班次、调剂掉的、还有没解决的。0、1、2 人的班取消了——因为不满 3 人；3 人以上的留下。那个没有教授的班，虽然满了，也取消。

\[马喆]: 那这些班里的学生怎么办？

\[倪成锦]: 如果他有备选能补，就在调剂里补上；补不上的，就是不足 4 门。

\[冯海洋]: 调剂只做一轮对吧？

\[倪成锦]: 一轮。学生按首次提交时间早晚排，时间一样的按学号小的排。然后按他备选的顺序一个个试，试到凑满 4 门为止。

\[马喆]: 那如果第一轮补进去的班后来又被取消了，会不会再补第二次？

\[倪成锦]: 不会。取消那一步在调剂之后，取消了就是取消了。

\[冯海伦]: 这一条我专门想了一个用例。学生先被调进一个只有 1 个人的小班，变 2 人，他另一门备选其实还有位置，但他这时候已经满了 4 门了；最后那个小班因为不满 3 人被取消。结果他是 3 门，而且备选不会再用第二次。

\[马喆]: 这个挺绕的。

\[冯海伦]: 对，但你不用就说不清「只有一轮」。

\[倪成锦]: 然后是计费。关闭之后，每个学生发一笔。这门课是每学分 125 块。屏幕上这个学生保留了三门，3 加 2 加 4 是 9 个学分，1125。另有一个从头到尾没提交过的学生，发的是 0 元。

\[冯海洋]: 0 元的也发？

\[倪成锦]: 发。需求里定了，没有课程也发一笔 0 元。

\[倪成锦]: 现在是计费系统故障重试。范昭你把计费模拟切成不可用。

\[范昭]: 切好了。

\[倪成锦]: 关闭。……你看，关闭是成功的，但是计费那一栏写着「等待发送」。等到它到 60 秒——这条我掐着表看过，59 秒的时候不重发，60 秒才发。

\[冯海伦]: 那这个我知道一个坑。我做测试的时候取快照取早了。我在服务端还没排空的时候就抓了数据，结果发现八百多个学生的客户端状态跟数据库对不上，我一度以为是数据坏了。

\[倪成锦]: 后来呢？

\[冯海伦]: 后来发现是脚本的顺序错了。测试结束的时候客户端还在轮流查询，我先把快照抓了，才去等服务端停下来。等它停了再对一次，是零错配。

\[范昭]: 所以那不是数据问题？

\[冯海伦]: 不是。那个 806 的数字我保留在报告里，但旁边写清楚了它的来历，不能拿它当「数据损坏」用。

\[倪成锦]: 对，这个处理是对的。宁可留着一个看起来难看的数字，也不要含糊过去。

\[倪成锦]: 最后是补选。这个是关闭之后才有的。

\[冯海洋]: 对。这个学生关闭之后只有三门。教务给他补一门，这门课还有位置、有教授、时间不冲突、先修也够。

\[冯海洋]: 补上了。然后计费那边会重发一笔更正后的。

\[浩宇]: 学生页面上能看到吗？

\[冯海洋]: 能。他原来是 1125，补完变成 1750。是替代原来那一笔，不是两笔加起来。要是加起来就是 2875 了，那是错的。

\[倪成锦]: 而且如果老的那一笔确认得晚，晚到的那个不会把新账退回去。

\[范昭]: 这个我模拟里验过：同一个学生、同一个学期，新版本到了以后，旧版本的确认晚到，最终账单还是新版本。

\[马喆]: 那如果他已经有四门了呢？

\[冯海洋]: 直接拒，说「已达四门」。不能靠删一门再补一门绕过关闭后退课的禁令。

\[倪成锦]: 好。主链路走完了。现在说性能。这条我来讲，因为是我改的。

\[倪成锦]: 上次冯海伦那个 2000 用户档没过，63%。我这两天的结论是这样：一个是本机瞬时建连会被重置，这个跟我们机器一个参数有关；第二个是真问题——目录同步那个队列是串行的，而且每个请求都串一次。排在后面的要等两百多秒。

\[倪成锦]: 我改了两处。第一处，同一个学期里还没开始的那一轮刷新，后面到的请求直接并到这一轮里，不再各自发起；已经开始的轮次不动，因为那会破坏新鲜的边界。第二处，目录查询只取它真正要用的几个字段和计数，不再把整个投影拉一遍。

\[倪成锦]: 中间我试过只改第一处，还是失败，27%。加上第二处，75%，还是失败。第三处——只读的那条路径也做下一轮合并——才过。

\[冯海伦]: 那最后一版跑了多少？

\[倪成锦]: 三分钟的短诊断是 26,996 笔全过。正式的 2000 用户、5 分钟预热加 30 分钟稳态，是 264,615 笔全成功、都在 120 秒内，目录 105,899 笔全在 10 秒内，排空以后 8,000 条有效注册，容量、每人最多四门、客户端跟数据库零错配。

\[马喆]: 那这个就是过了？

\[倪成锦]: 过了要求，但不能说全面通过。

\[马喆]: 为什么？

\[倪成锦]: 三个原因。第一，官方的做法是另一台机器、独立网络，我们还是在同一台机器上跑，只是分了进程。第二，我们上次是 macOS 跑的，这次是 Linux，环境不一样，不能直接说 macOS 上也好了。第三，p95 是 6.4 秒，最大值 9.92 秒——目录门槛是 10 秒，就差那么一点。换个机器、加个网络时延，很容易就超了。

\[范昭]: 那要不要再在 macOS 上跑一遍？

\[倪成锦]: 要，但那属于补测，不阻塞这轮。

\[冯海伦]: 我保留原来的失败结果，不会拿这个新的去把老的覆盖掉。

\[倪成锦]: 对，两个都留着。老的写环境是 macOS、失败，新的写环境是 Linux、通过。谁来看都能看出来这是两个环境。

\[倪成锦]: 还有两个没关的。一个是刚才那个超时客户端的事。测试客户端超时了，但服务端可能还在处理，客户端的本地状态最后可能跟数据库不一致。我故意用 1 毫秒超时复现了，15 个客户端对不上。

\[冯海伦]: 那这个算数据问题吗？

\[倪成锦]: 不算。数据库本身是一致的。是客户端在超时之后没有重新读一次。这个属于测试工具的问题，也属于我们没法保证的事——真实用户在超时的时候也会这样。它不影响数据，但影响我们能不能说「全都一致」。所以挂着，不关。

\[冯海伦]: 那第二个呢？

\[倪成锦]: 第二个是 Windows 和 Edge 一直没测。非功能要求里写的是 Windows 上当前的 Chrome 和 Edge。我们现在只有 macOS 的 Chrome。

\[范昭]: 这个机器上就一台 Windows。

\[倪成锦]: 那也得测。这条挂到下一轮。

\[冯海伦]: 那我说我这边。

\[冯海伦]: 逐 AC 的账本现在是一条一条填的，64 条。状态有「通过」「部分」「未执行」三种。通过的是主路径，还有权限、并发、故障那几组。

\[马喆]: 「部分」的有多少？

\[冯海伦]: 一批。主要三类：一是页面上的各种组合，比如空结果、错误提示、各种状态的组合，我只覆盖了常见的；二是故障注入，我注入了几个点，不是每个点都注；三是审计，我抽查了几类操作，没有逐条把每个事件的字段都对完。

\[倪成锦]: 那我问一句，凭现在这个状态，你敢不敢说一句「这个系统可以交付」？

\[冯海伦]: 不敢。分两块说：功能主链路我敢说能用；「64 条都验过了」我不敢说。而且非功能里七天可用性那条，我根本没测，那个要连着观察，我们没这个时间，我不会拿 70 分钟压测去换算出个可用性数字。

\[倪成锦]: 好。那这个就是今天的结论：不声称全部验证通过。

\[马喆]: 那已修的那个界面问题算哪块？

\[倪成锦]: 你是说计费表那个？

\[马喆]: 对，就是演示的时候发现的那个——计费表上只有一串 UUID，看不到学号姓名；还有宽度小一点的时候，按钮被截掉一半。

\[倪成锦]: 那个已经修了，改了之后是 14 个文件 219 项测试。是演示前评估的时候发现的，登记成 BUG-001。它算下一轮的收尾，不算这轮的交付。

\[马喆]: 那我们就剩三天了。

\[倪成锦]: 对，所以今天要定范围冻结。我的意见是，从明天，也就是 10 月 12 号起，除了修缺陷，不再加任何功能。

\[范昭]: 包括「导入结果能导出」那条？

\[倪成锦]: 包括。那条是锦上添花，不是题目要求的。

\[范昭]: 行，那我把它列进「明确不做」里。

\[马喆]: 那如果最后两天发现一个必须修的问题呢？

\[倪成锦]: 缺陷照修。我说的是不加新功能。这两个不一样。

\[冯海洋]: 同意。

\[浩宇]: 同意。

\[倪成锦]: 那这轮的结论：主链路六段都过，性能修复合入但保留原失败，独立验收是「进行中、含一批部分」，范围从明天冻结。打 tag 的话，我倾向于 v0.3.0，同样的规矩，发布记录里写清楚它覆盖什么、没覆盖什么。

\[冯海伦]: 可以，但我要在记录里留一句「本版本未完成独立验收」。

\[倪成锦]: 留。

\[倪成锦]: 回顾。三个问题。

\[浩宇]: 做得好的：这轮我把学生端从头到尾自己走了一遍，不是只跑单元测试。有几个问题就是这么发现的。

\[冯海洋]: 我觉得好的是把「影响预览」做出来了。改一个人状态之前能先看到会发生什么，这个对教务来说是真的有用。

\[马喆]: 我说个做得不好的。性能那个事，我这两天在按「性能没问题」的假设改东西。如果一开始就知道 2000 用户那档没过，我可能会少改一点。

\[倪成锦]: 这个上次也提过，坏消息不过夜。看来还没完全改过来。

\[冯海伦]: 我提一个另外的。我的测试报告写到第 7 节的时候，只剩退出条件了，但是我一直没有明确写一句「哪些是我验的、哪些是别人自测的」。这个区别很重要，我一开始混在一起写，读的人会以为是同一回事。

\[范昭]: 我说不好的：模拟系统那块的说明文档，我改了三次。每次都是别人来问我才发现问题，说明我写得不够细。

\[倪成锦]: 那我认一条。性能那个排查，我一开始的假设是「连接的问题」，第一轮打掉之后才发现真正的大头是目录队列。中间那两轮短诊断其实可以更快。

\[倪成锦]: 「下一轮要改的一件事」。候选：一是把所有「部分」的账本条目补完；二是把交付材料按课程封面定稿；三是 Windows 上跑一遍。

\[冯海伦]: 我觉得得选账本。补不完的话，我们最后交出去的东西说不清楚到底验了多少。

\[马喆]: 但是我担心那个补不完。

\[冯海伦]: 补不完就写「未完成」，但不能是模糊的「部分」。

\[倪成锦]: 那定：账本每一条要么写出结论，要么明确写未执行，不许留「部分」这种含糊状态。其他的按时间尽量。

\[浩宇]: 同意。

\[倪成锦]: 那就散会。我明天把范围冻结这条更新到计划里。

\[范昭]: 拜拜。
