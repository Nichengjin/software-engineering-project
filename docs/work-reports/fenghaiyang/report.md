## 二、领域内已形成的成果

**人员维护。** 教务页支持师生搜索、分页、新建、修改、删除及账户停用。列表以账号和人员 ID 区分同名人员，不能用姓名作为唯一身份；接口以跨角色 SSN 身份记录防重，页面只显示脱敏值，编辑留空 SSN 表示保持原值。新建凭据只在本次响应显示，不保存到浏览器。由在读／在职转为非活跃状态前先预览关联学期与班次，说明未关闭记录清理及已关闭历史保留，再携带确认 token 写入；账户停用本身不自动退课。已有业务历史不能硬删除，应改状态或停用，无业务记录人员可经确认删除。

**批量导入。** 页面提供学生、教授、历史成绩、授课资格四类真实 xlsx 上传，展示原 Excel 行号及成功、重复跳过、拒绝和原因。解析采用严格表头与限额，SSN、编号须用文本保留前导零，公式、链接和数值编号会被拒绝。有效行独立事务处理，坏行不撤销前面成功行；历史成绩仅允许上线学期以前的数据，不覆盖已有成绩，资格按教授与课程去重。初始密码不能通过重复导入重新取得，响应丢失时页面不自动重传。

**学期与结算操作。** 窗口按北京时间输入显示、转换为 UTC 请求，起点包含、终点不包含；提交保留原 expectedVersion，服务器新版本到达不直接覆盖未保存副本，冲突需重新确认。关闭页区分请求接收、CLOSING 和最终完成，分别呈现取消、调剂、未解决问题及账单版本、金额、送达状态，避免把接受请求当成功。补选页展示在读学生和班次可选条件，携带原课表版本确认；成功提示生成完整新版账单，需继续核对送达，不将新旧金额相加。

## 三、两个有证据的设计难点

**预览与确认之间的状态变化。** 只弹出“确认”不足以保证人员清理安全，因为课表、学期或关闭 gate 可能在两次请求间变化。人员服务把版本、规范化修改内容、影响集合指纹及五分钟有效期绑定到签名 token，写事务重新计算，变化则要求重新预览。删除与关闭之间还需学期行锁和 gate 复查。这是源码及设计记录支持的并发设计难点，不是本人曾复现并解决该竞争的经历。

**部分成功与敏感凭据的交付。** 导入不能只返回整体“成功”：严格表头、重复身份、非法行和历史边界需要分别反馈，同时合法行已经落库。逐行事务与三类结果使教务能定位并修正输入，但一次性密码意味着重导不能恢复凭据。真实开发联调记录有三行一成功、一重复、一拒绝，并在隐藏凭据后检查页面及删除新增人员；该记录证明开发链路，不证明本人执行，也不覆盖全部恶意文件组合。
