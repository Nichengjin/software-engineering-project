## 本人修改与团队汇总

每份报告从成员负责领域出发，依据需求、设计、源码、提交和测试记录展开工作过程。2026-10-08用户确认代码由成员与Agent协作完成、决策均由人类负责；Amp名称主要来自统一撰写提交信息。报告采用这一协作事实，不把工具署名解释为成员未参与，也不把未提供的具体经历、独立验收或审批补成事实。

1. 本人逐段确认职责、技术叙述与成果，补充实际发起、设计、审核、修改、测试或沟通的具体内容。第一人称的领域工作叙述包含已确认的人机协作，不等于所有操作均由本人手工执行。
2. 搜索 `【待本人补充】`，加入真实时间、具体输入／预期／实际结果、遇到的问题、处理与回归、个人收获、尚未完成事项；可附提交、评审或脱敏记录。没有执行的工作保留未参与／未测状态。
3. 不把技术设计难点直接改写为亲历缺陷；不把全项目回归数量当作个人测试量。原 macOS 失败与后续 Linux 通过分别保留，环境差异和未覆盖项不能删去。
4. 六人完成个人修订后，组长核对小组总结中的 `【待团队补充】` 和 `【待团队确认】`，以真实工作记录确认贡献比例，六人合计100%；再补齐组号、封面和签名。
5. 最终统一材料格式并核对程序运行检查结果。初稿形成不等于课程验收、正式提交或发布完成。

## 每份文档的附件放在自己的目录

各人在自己的报告目录维护 `attachments/`；全组图表或签字材料放 `team/attachments/`。倪成锦v0.2包含保存无注册、正式提交、冲突保留旧注册、关闭与计费送达四张实际截图，环境、前置数据与断言见其报告第十章。本轮其余报告复用2026-10-06验收截图，并按各自场景说明来源和限制；共享UML图使用相对引用，不重复复制源模型。

历史截图的采集日期与本轮整理日期分别标注，页面上的固定业务时间不当作拍摄时间。新增图片只引用实际存在的文件，注明被测环境、输入和结果；截图与测试断言配合说明场景，不替代未执行的验证。

附件须隐藏密码、token、完整SSN及真实个人数据；不要上传 `.env`、私有凭据文件、数据库转储或未脱敏日志。体积大的录像等材料先确认保存与分享方式，不直接堆入仓库。
