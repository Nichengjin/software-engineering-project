## 一、目标与团队责任

我们以 Wylie College 为场景，建设学生、教授、教务员三角色课程系统。学生浏览课程、保存与提交课表、加退选及查成绩；教授选择授课、查看名册和逐项录分；教务员维护人员、导入资料、设置窗口并关闭选课、调剂和补选。外部课程目录只读，计费由独立 HTTP 模拟接收，实际支付不在范围内。目标不仅是界面可演示，还包括权限隔离、容量与事务一致性、故障恢复及可复现证据。

## 三、具体成果与问题处理

需求先澄清再建模：[需求分析](../../REQUIREMENTS_ANALYSIS.md)区分题目要求、项目解释与修改，[OOA](../../design-docs/object-oriented-analysis.md)识别领域对象和交互，再进入[总体设计](../../design-docs/system-design.md)及[API契约](../../design-docs/api-contract.md)。9张设计图涵盖部署、组件、四组数据关系和三条关键时序，有原生 StarUML 源及导出检查，不是九张截图替代模型；分析图与设计图不混计。

实现采用 React／Vite／TanStack Router、Hono、Prisma／PostgreSQL，划分 API、Web、模拟器与共享契约。保存不占名额，正式提交执行容量10人、先修与冲突校验；版本约束拒绝旧请求。关闭采用准入排空与原子事务，账单同事务写入 outbox，60秒重试和版本替换支持重启恢复。浏览器已联通三角色及真实数据库、模拟服务，但架构明确为单实例，不能推断多实例能力。

我们从已有记录中选出三类真实问题，避免只列成功成果：

1. **授课历史时钟不一致。** 完整回归出现130通过、3失败：创建时间取数据库真实时间，结束时间却取业务时钟，违反时间顺序约束。先补首次选择、7秒后取消、11秒后重选的精确复现，再显式使用 `rt.now(tx)`，没有修改日期或约束掩盖错误；[修复655ad72](https://github.com/Nichengjin/software-engineering-project/commit/655ad72c43dcc5a4b970642694467c4351fb600f)与[检查history](../../histories/2026-10/20261005-merge-checks.md)保留闭环。
2. **私有仓库CI与依赖阻塞。** Dependency Review能力不支持，改用完整lockfile的npm high门禁并保留OSV，明确不等价于许可证增量比较。限定消费者升级deepmerge-ts／uuid，验证安装、审计及ExcelJS真实写读；课程来源只修Markdown格式，不改正文。最终134项业务回归、构建及远程检查通过，未将审计零漏洞解释为零风险。
3. **目录吞吐不能靠单次猜测修好。** 原2000档失败后，观察连接重置与目录长队列；Linux TCP对照未复现macOS重置，但不证明系统无连接限制。三轮2000用户短诊断依次只合并写刷新、缩小查询、再合并只读下一轮，达标交易比例为27.03%、75.12%、100%。前两次失败保留；第三轮后才做正式长测。共享尚未开始的下一轮保持请求后的新鲜度边界，全局锁与120秒期限未放宽，详见[目录history](../../histories/2026-10/20261007-1918-catalog-throughput.md)。

## 四、测试结果与边界

[测试报告v0.3](../../TEST_REPORT.md)与[逐AC账本](../../testing/acceptance-execution.md)是结果入口。测试数按阶段列出，不能相加成独立用例总数，也不能换算64条AC的通过率。

验收使用随机独立数据库、真实HTTP模拟和非对称数据，手写预期金额与竞争结果，不调用产品规则计算答案。已执行末席竞争、权限伪造、数据库故障回滚、真实进程重启与六十秒重试。提交前发现重启测试在首次目录同步完成前取基线，只补等待条件，保留完整快照与幂等断言后重新通过全量回归。这些证据说明测试也需验证自身假设；测试驱动或环境问题不应冒充产品缺陷，自动执行更不能冒充成员本人验收。
