## 一、职责与工作范围

我的责任范围是教授端授课选择、学生名册、成绩录入的页面与接口，以及相关详细设计核对、自测和缺陷闭环。对应 US-009—011，涉及教授身份、授课资格、班次归属、正式注册和成绩权限，与统筹的认证／事务、学生端注册、教务人员及学期配置协作。[角色指南](../../member-guides/mazhe.md)要求重点核对资格与冲突、名册范围、所有权和成绩值，不制造提交。后续本人参与应以实际修改、运行记录和审核意见补证，而非从职责表推定已经完成。

## 二、教授端已形成的成果

授课服务采用整份安排替换：开始时间前不能选择，关闭期间由准入机制阻断，已关闭学期拒绝修改；服务端检查资格、班次存在与开放状态、他人占用和时间冲突，并复查目录版本及 `expectedVersion`。确认后在事务内更新归属、历史、版本和审计。撤销会释放班次并结束历史，不删除历史记录；若整份安排校验失败，不能出现“新增失败但旧班次已撤销”的半完成状态。两个教授争抢同一班次，由事务锁内复查保证至多一个成功，不依赖前端禁选。

教授页面显示资格和占用提示，保留独立本地编辑副本。服务器版本变化时不覆盖未保存编辑，而是提示对照并禁止旧版本提交，确认后才采用服务器安排；冲突请求不自动重发。这解决了轮询刷新与人工编辑之间的冲突，但按钮状态只是交互帮助，权限仍由 API 决定。

名册只允许本人负责班次访问，来源是有效正式注册，不把保存的主选或备选算作学生。响应包含学号、姓名和成绩，不提供 SSN。录分仅面向上一已完成且不早于上线学期的本人班次：先检查整份请求的学生归属，混入非本班学生就整份拒绝，已有成绩不变；通过权限后逐格处理，A、B、C、D、F、I 可保存，空白或 null 保持旧值，Z 等非法值只拒绝对应格。页面展示逐格结果并保留失败输入，不支持以空白清除成绩。这里必须区分“有值的 I”与“未录入的 null”，也必须区分业务非法值与越权请求，避免部分成功削弱权限边界。

## 三、真实问题与设计难点

集中合入前发现授课历史使用两套时间来源：`createdAt` 由数据库默认真实时钟生成，`endedAt` 却取业务时钟，固定测试时钟早于数据库时间时违反 `time_order` 约束。[合入检查记录](../../histories/2026-10/20261005-merge-checks.md)保留首次完整回归 130 通过／3 失败，以及补充 AC14／51 回归先失败的过程。修复显式使用 `rt.now(tx)`，断言开始、七秒后取消、十一秒后重选的新历史，不通过改测试日期或去掉约束掩盖问题。修复提交 Author 为倪成锦，不能写成马喆独立发现或修复。

这项案例说明，历史记录不仅要“能写入”，还要与可注入业务时间一致。其他难点是把跨教授竞争、撤销原子性和版本冲突统一在服务端事务中，以及在逐格容错之前完成整份授权。上述认识是基于源码与记录的整理；本人实际理解过程和取舍讨论仍需补充。
