人机界面设计

n 人机界面可以看作是基于计算机的系统或产品的最重要的

元素；
n 不好的人机界面将严重地阻碍用户使用系统的计算能力；

n 一个弱的界面可能导致一个很好设计和可靠实现的应用的

失败。

人机界面设计的黄金规则

n 赋予用户控制权
 n 以不强迫用户进入不必要的或不希望的动作的方式来定义交
  互模式；
 n 提供灵活的交互；

 n 允许用户交互可以被中断和撤销；

 n 当技能级别增长时可以使交互流水化并允许定制交互；

 n 对用户隐藏内部技术细节；

 n 设计应允许用户和出现在屏幕上的对象直接交互。

人机界面设计的黄金规则


  n 减少用户的记忆负担

   n 减少对短期记忆的要求；

   n 建立有意义的缺省；

   n 定义直觉性的捷径；

   n 界面的视觉布局应该基于真实的世界；

   n 以一种渐进的方式展示信息。

n   帮助设施：分为集成的和附加的两类；
n   具体设计帮助设施时，必须解决的问题：
    n   在用户与系统交互期间，是否在任何时候都能获得关于系统任何功能的帮助
        信息?（提供部分功能的帮助信息和提供全部功能的帮助信息）
    n   用户怎样请求帮助?（帮助菜单、特殊功能键和HELP命令）

        显示简短提示）
    n   用户怎样返回到正常的交互方式中?（屏幕上的返回按钮和功能键）
    n   怎样组织帮助信息?（平面结构、层次结构和超文本结构）

n 出错信息处理
 n 出错信息设计得不好，将向用户提供无用的甚至误导的信息，反而
  会加重用户的挫折感。
 n 有效的出错信息能提高交互式系统的质量，减轻用户的沮丧感。

 n 交互式系统给出的出错信息或警告信息应具备的属性：

  n 信息应该用用户可以理解的术语描述问题。

  n 信息应该提供有助于从错误中恢复的建设性意见。

  n 信息应该指出错误可能导致哪些负面后果。

  n 信息应该伴随着听觉上或视觉上的提示。

  n 信息不能带有指责色彩。

人机界面设计指南

  n 一般交互指南
   n 保持一致性；

   n 提供有意义的反馈；

   n 在执行有较大破坏性的动作之前要求用户确认；

   n 允许取消绝大多数操作；

   n 减少在两次操作之间必须记忆的信息量；

   n 提高对话、移动和思考的效率；

   n 允许犯错误；

   n 按功能对动作分类，并据此设计屏幕布局；

   n 提供对用户工作内容敏感的帮助设施；

   n 用简单动词或动词短语作为命令名。
                             22
人机界面设计指南

  n 信息显示指南
   n 只显示与当前工作内容有关的信息；

   n 不要用数据淹没用户；

   n 使用一致的标记、标准的缩写和可预知的颜色；

   n 允许用户保持可视化的语境；

   n 产生有意义的出错信息；

   n 使用大小写、缩进和文本分组以帮助理解；

   n 使用窗口分隔不同类型的信息；

   n 使用“模拟”显示方式表示信息；

   n 高效率地使用显示屏。

                             23
人机界面设计指南

 n 数据输入指南
  n 尽量减少用户的输入动作；

  n 保持信息显示和数据输入之间的一致性；

  n 允许用户自定义输入；

  n 交互应该是灵活的，并且可调整成用户最喜欢的输入方式；

  n 使在当前动作语境中不适用的命令不起作用；

  n 让用户控制交互流；

  n 对所有输入动作都提供帮助；

  n 消除冗余的输入。
