    软件项目中的人员

n   项目干系人（Stakeholder）
    u 项目干系人指的是那些在项目上有既得利益的人，项目的结果
      对他们而言意味着某种得失。
    u 关键项目干系人能够促成或破坏项目的成功。即使项目实现了

      所有的可交付成果并且达成了所有的目标，如果关键项目干系
      人不满意，全都白费。
    软件项目中的人员

n   项目干系人（Stakeholder）
    u 高级管理者：负责定义业务问题；
    u 项目（技术）管理者：计划、激励、组织和控制软件开发人员；

    u 开发人员：负责开发一个产品或应用所需的专门技术；

    u 客户：负责说明待开发软件的需求的人以及其他风险承担者；

    u 最终用户：直接与产品交互的人。
    软件项目中的人员

n   项目干系人（Stakeholder）
    u 一定要在项目的最初阶段会见所有的关键项目干系人，理解他
      们的需求和约束；
    u 项目干系人之间往往存在利益冲突；

    u 解决项目干系人冲突的时候永远要以对客户有利为出发点；
人员组织


n 为了成功地完成软件开发工作，项目组成员必须以
一种有意义且有效的方式彼此交互和通信。
n 项目组组织得越好，其生产率越高，而且产品质量
也越好。
民主制程序员组


n 小组成员完全平等，享有充分民主，通过协商做
  出技术决策。
n 小组成员之间的通信是平行的：如果小组内有n
  个成员，则可能的通信信道共有n(n-1)/2条。
民主制程序员组

n 一般说来，程序设计小组的规模应该比较小，以
 2~8名成员为宜 。
n 民主制程序员组通常采用非正式的组织方式 。

n 主要优点 ：

 n 组员们对发现程序错误持积极的态度 。

 n 组员们享有充分民主．小组有高度凝聚力，组内学术
  空气浓厚，有利于攻克技术难关。
n 主要问题：

 n 软件开发人员多数比较缺乏经验；

 n 程序设计过程中有许多事务性的工作，例如，大量信息
  的存储和更新；
 n 多渠道通信很费时间，将降低程序员的生产率。
主程序员组

n 主程序员组用经验多、技术好、能力强的程序员
  作为主程序员，同时利用人和计算机在事务性工
  作方面给主程序员提供充分支持，而且所有通信
  都通过一两个人进行。
n 主程序员组的两个重要特性： 专业化和层次性。

主程序员小组


n 主程序员：既是成功的管理员，又是高度熟练的程序
 员，要负责体系结构和其他关键复杂部分的设计，协
 调其他成员，复查其他成员的工作，对每行代码负责。
n 后备程序员：主程序员的“替补”，要和主程序员一
 样能干。
n 编程秘书：负责完成与项目有关的全部事务性工作，
 例如，维护项目资料库、文档，甚至源码的编译、链
 接、运行等。
主程序员小组存在的问题


 n 主程序员很难找到：成功的管理员、高度熟练的程序员的结
  合体；
 n 后备程序员更难找到：高能力、高素质却要甘居“全场替补
   板凳队员”；
 n 编程秘书也不容易找到

    人员与工作量之间的关系
n   在项目后期增加人手通常产生一种破坏性影响，其结果是使进度
    进一步拖延。
n   参加软件项目的工作人员数量与整体生产率之间的关系不是线性
    的。
    u   成员间通信路径的增加会增加额外的工作量
n   开发同一个软件（规模固定），如果把项目持续时间延长一些，
    则可降低完成项目所需的工作量，即可以用较少的人在稍长一点
    的时间内完成同样的任务。
