能力成熟度模型
过程与产品质量

n 软件的质量依赖于设计过程，个人技术和经验对软件产品的影响
 是巨大的。
n 如果思路是降低个人影响带来的不确定性、提高设计过程对产品
 的影响，则过程质量对软件产品的质量有重大影响：
 n 过程中有相关的质量管理标准；

 n 质量管理要求对过程进行监控；

 n 过程需要定时向管理层或客户反馈项目进展；

n 创新、市场压力等会改变上述思路的重要性。
过程与产品质量


   n 影响软件产品质量的四个因素：


          n 过程质量
          n 人员素质
          n 开发技术
          n 成本、时间和进度
过程与产品质量



n 大型系统：软件过程是决定性因素，因为主要问题
  是集成、项目管理和沟通。
n 小项目：开发团队的人员素质更重要。
过程与产品质量


n 小团队：好的开发技术、工具很重要。

n 预算偏低或进度计划不现实对任何项目的产品质量都
 会有影响。
n 通常软件存在问题的真正原因源于开发机构受到的生
 存压力：为赢得开发机会故意压低项目预算。
能力成熟度模型（CMM）


n CMU-SEI是一个由美国国防部（DoD）资助的研究机构。

n 80年代中期，SEI启动了对DoD承包商能力评估方法的研究。

n 1987年发布软件过程成熟度框架简短描述，以及Watts Hamphrey扩
  充的软件过程评估方法、软件成熟度评价方法、成熟度问卷。
n 1991年SEI推出并评审通过CMM 1.0。

n 1993年修订为CMM 1.1。
能力成熟度模型（CMM）

n 持续的过程改进基于许多细小的、逐渐发展的步骤，而不是革命
 性的革新。CMM提出的框架中，将这些步骤组织为五个成熟度等
 级，为持续的过程改进提供了基础：

        n 等级1：初始级（Initial）
        n 等级2：可重复级（Repeatable）

        n 等级3：已定义级（Defined）

        n 等级4：已管理级（Managed）

        n 等级5：优化级（Optimizing）
能力成熟度模型（CMM）

n 一个成熟度等级是经过严格定义的、且达到成熟软件过程的发
  展阶梯。
n 每个成熟度等级由一组过程目标集合（关键过程域）组成。
n 该模型的使用有两种方式：
 n 潜在的客户使用该模型以确定软件供应商的能力和弱点。

 n 软件供应商使用该模型以评估自己的能力并找出改进的途径。
等级1：初始级（Initial）

n 初始级描述了一个无序（或混乱）的过程。该过程从输入到
 输出的转换没有定义且缺乏控制，过程可见度为零，很难进
 行全面的度量。
n 由于缺乏适当的结构与控制，即使是相类似的项目也可能在
  生产率和质量上有很大不同。
n 开发的成功依赖于个人的努力，而不是团队的合作。

n 处于该级别的机构应致力于引入适当的过程结构以及项目管
  理规程。
n 这个级别没有关键过程域（KPA）。
等级2：可重复级（Repeatable）


  n 确定了过程的输入和输出、约束、资源

  n 具有严格的控制来跟踪成本、进度和功能

  n 小组成员间有一些纪律制度，以便以前的成功项目能在新的
    类似项目中重复
  n 对需求和产品建立了基线，并控制其完整性

  n 这个等级的关键问题是培训、技术评审、标准
等级2：可重复级（Repeatable）

      n 等级2的关键过程域    ：
       n 需求管理

       n 软件项目计划

       n 软件项目的跟踪及监督
       n 软件转包合同的管理

       n 软件质量保证

       n 软件配置管理
等级3：已定义级（Defined）

n 该等级过程中管理和工程活动被文档化、标准化和集成化，形
 成了对机构中每个人都是标准的一个过程。
n 虽然项目之间可能有所不同，但可以对标准过程进行剪裁从而
  适应这些特殊需要，而这种修改必需经过管理层的批准。
n 该等级在等级2的基础上提高了过程的可见性，它定义了过程
  的中间活动，这些活动的输入输出都是已知的、被理解的，从
  而它们可以被检查、度量和评估，进而可以据此度量产品的属
  性，并尽可能在过程早期发现和纠正问题。
等级3：已定义级（Defined）

      n 等级3关键过程域：
       n 机构过程关注点

       n 机构过程定义

       n 培训计划
       n 集成软件管理

       n 软件产品工程

       n 开发小组间的协调

       n 同级评审
等级4：已管理级（Managed）

n 通过对过程和产品质量引入详细的度量，开发机构可以把重点放
在使用定量信息以使得问题可见，并评估可能的解决方案的效果。
n 该等级中，反馈决定了资源怎样分配，但并不导致过程的基本活
动发生改变。
n 可以对中间活动进行评价，用收集到的度量来稳定过程，以使生
  产率和质量符合要求。
n 与等级3不同，等级4中的度量反映了总体过程特性、主要活动中
  及活动之间的交互特性，而度量数据库可以提供有关错误分布、
  生产率和任务有效性、资源分配等过程特征信息，并比较计划值
  和实际值匹配的可能性。
等级4：已管理级（Managed）


      n 等级4的关键过程域：
       n 定量过程管理

       n 软件质量管理
等级5：优化级（Optimizing）


 n 该等级过程中包含了定量的反馈用以产生持续的过程改进。

 n 机构能有办法识别过程中的优势和薄弱环节，并预先予以
   防范。
 n 该等级还包括对新的工具和技术进行测试与监控，以了解
   它们对过程和产品的影响。
等级5：优化级（Optimizing）

       n 等级5的关键过程域：
        n 预防故障

        n 技术变更管理

        n 过程变更管理
理解CMM时的注意事项

n 成熟度仅表示了从1到5级连续区间中的相对位置，目标是希
  望软件机构能持续地改进自己的过程，并非要定义五个离散
  的等级；
n 改进和评估可以在过程的很多方面同时进行，某些方面可能
  做得比其它方面更好而超出了当前过程的整体评估等级；
n CMM是对软件过程改进领域的重要贡献，但不应该把它视为
  一种适应所有软件过程的权威性能力模型。不要忽略这个模
  型设计的初衷：为DoD提供评估软件开发商能力的手段。
理解CMM时的注意事项


n 开发国防软件与开发商业软件之间有很大不同：
 n 开发非常大型的软件系统出现的问题不一定所有软件机
  构都能遇到；
 n 商业软件开发需要能更快地响应技术上、业务领域上的
  变化；
 n 国防软件有一个很长的购买过程和很长的生存期，因此
  在采用新技术上更趋于保守。
