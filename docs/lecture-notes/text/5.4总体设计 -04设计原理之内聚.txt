模块独立性：内聚

n 内聚（ Cohesion ）标志一个模块内各个元素彼此结合的紧密程
 度，是模块功能强度的度量，用来量化表示一个模块在多大程
 度上专注于一件事情。一个模块内部各个元素彼此结合得越紧
 密，内聚度就越高，模块独立性就越强

n   偶然内聚（Coincidental Cohesion）：还有下一次吗？
n 当模块内各部分之间没有联系，或者即使有联系，这种联系也很松散，则称
  这种模块为偶然内聚模块，它是内聚程度最低的模块
n 例如，一些没有任何联系的语句可能在许多模块中重复出现多次，程序员为
  节省存储，把它们抽出来组成一个新的模块，得到偶然内聚模块。

n 逻辑内聚（Logical Cohesion）：逻辑组合关系是千变万化的
 n 这种模块把几种相关的功能组合在一起，每次调用时，由传送给模块的判
  定参数来确定该模块应执行哪一种功能；
 n 是单接口多功能模块，类似的有错误处理模块，接收错误代码，作出不同
  的响应。
n 存在的问题：
 n 不是执行一种功能，而是若干功能中的一种，因此它不易修改；

 n 调用它时要传递控制参数，形成控制耦合；

 n 将未用的部分也调入内存，降低系统效率；

n 时间内聚（Classical Cohesion）：时序问题不止是千变万化……

n 这种模块大多为多功能模块，但模块的各个功能的执行与时间
 有关，通常要求所有功能必须在同一时间段内执行，例如初始
 化模块和终止模块
n 时间内聚比逻辑内聚强一些，因为时间内聚模块中各个部分都
  要在同一个时间段内执行，而且一般情形下，各部分可以按顺
  序执行，所以其内部存在的逻辑判定转移更少
n 但要注意时序问题
n 过程内聚（Procedural Cohesion）：“程序流程图的一部分”

n 使用流程图作为工具设计程序时，把流程图中的某一部分划出
 组成模块，就得到过程内聚模块。例如，把流程图中的循环部
 分、判定部分、计算部分分成三个模块，这三个模块都是过程
 内聚模块
n 过程内聚模块仅包含完整功能的一部分，所以它的内聚度仍较
 低，造成的模块间的耦合度还是较高

n 顺序内聚（Sequential Cohesion）：接近单一
n 一个模块内的处理元素和同一个功能密切相关，而且这些处理必
  须顺序执行，通常一个处理元素的输出数据作为下一个处理元素
  的输入数据
n 根据数据流图划分模块时，通常得到顺序内聚的模块。

n 功能内聚（Functional Cohesion）：只做一件事

n 一个模块中各个部分都是完成某一具体功能必不可少的组成部
 分，或者说该模块中所有部分都是为了完成一项具体功能而协
 同工作，紧密联系，不可分割的。则称该模块为功能内聚模块。
n 这种模块易于修改和维护，因为它们的功能是明确的，模块间
 的耦合是简单的。
