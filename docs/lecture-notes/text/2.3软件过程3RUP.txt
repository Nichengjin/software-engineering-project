 4. Model Software Visually

n Capture the structure and behavior of architectures and components

n Show how the elements of the system fit together

n Maintain consistency between a design and its implementation
n Promote unambiguous communication
5. Verify Software Quality

n Create tests for each key scenario to ensure that all requirements are
  properly implemented
n Unacceptable application performance hurts as much as unacceptable
  reliability
n Verify software reliability - memory leaks, bottle necks
n Test every iteration - automate test!
6. Control Changes to Software
n Control, track and monitor changes to enable iterative development

n Establish secure workspaces for each developer
   n Provide isolation from changes made in other workspaces
   n Control all software artifacts - models, code, docs, etc.

n Automate integration and build management

RUP术语(RUP Terminology)
n Worker
   n   a Role played by individuals on a project
   n   some people have many roles
n Activity
   n   a unit of work with a clear purpose, broken down into steps
   n   small, definable, reusable tasks that can be allocated to a single worker
n Artifact
   n   a work product produced as a result of an activity
   n   usually process deliverables, like: use cases, code, plans, test cases, test results
n Workflow
   n   The sequence of activities performed in a business that produces a result of observable
       value to an individual actor of the business.

RUP软件开发生命周期的动态结构

n 工作阶段
 n Inception（先启）：生命周期目标里程碑
  n   建立业务模型，定义最终产品视图，确定项目的范围
 n Elaboration（精化）：生命周期架构里程碑
  n   设计并确定系统的体系结构，制定项目计划，确定资源需求
 n Construction（构建）：初始可操作性能里程碑
  n   开发所有构件和程序，集成为客户需要的产品，测试所有功能
 n Transition（移交）：产品发布里程碑
  n   把开发出的产品提交给用户使用
RUP迭代式开发

n 整个项目开发过程由多个迭代过程组成。

n 每次迭代只考虑一部分系统需求。

n 每个迭代都是风险驱动的。

n 每个迭代都可以看作是一个“小型的瀑布模型”过程。
 n 以一个交付版本结束

 n 其结果是一个增量，增加一些新的功能

n 每次迭代以不同的重点和强度访问核心工作流。

RUP生命周期的特点

n 与螺旋模型相比

 n 相似：重复一系列组成系统生命周期的循环
 n 差异：
  n   RUP给出了每个阶段内的若干次迭代过程完成后交付的增量的具体要求，
      即四个阶段的里程碑
  n   RUP详细阐述了不同阶段的不同迭代过程经历的九大核心工作流程中活
      动内容的重点和强度不同
  n   RUP提供了对每次迭代过程中不同核心工作流程活动的并行化支持
n 优点：用于指导需求不明确、不稳定的项目开发时具有更强的可操

      作性。
RUP生命周期的特点

n 与瀑布模型相比

 n 优点：
  n RUP将成本风险进一步降低为获得一次增量所需的费用

  n RUP进一步降低了产品不能按计划投放市场的风险

  n RUP使项目开发更能适应项目需求的变化
RUP的人员——角色及其活动

n 角色的划分及相关活动

 n RUP定义了五大类角色集：分析员、开发人员、测试员、经理、
   其他角色。每一类角色集又包括多个角色，并给出了每个角色对
   应的活动。
 n 角色的意义
  n   将角色和个体区分开来，有效提高了项目中人力资源的利用率。
 n 角色方面的缺陷
  n   未给出角色的组织管理方式、角色间的相互地位关系和交互方式。

 RUP的特点

n 优点：

 n 用例驱动、以架构为中心、迭代和增量；

 n 具有二维迭代性，有利于降低风险、适应需求变化；
 n 是可配置的，具有通用性；

n 缺点：

 n 在理想的项目开发环境下软件过程的一种完美模式；
 n 未给出具体的剪裁、扩充等配置实施的方法准则。
