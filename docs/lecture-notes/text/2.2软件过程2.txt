阶段式开发（演化模型）


n 软件系统和其他所有复杂系统一样，是随着时间不断演
  化的。业务需求和产品需求随着开发向前推进经常发生
  改变，这使得直线式的开发模型不切实际。
n 来自时间、成本、人力以及技术等方面的压力往往使得
  演化成为软件开发的必经之路。
n 阶段式开发大体分为两种：
 n 渐增式开发

 n 迭代式开发（螺旋式开发）
阶段式开发（演化模型）
增量模型(渐增模型)


n 增量模型把软件产品作为一系列的增量构件来设计、
  编码、集成和测试。
n 每个构件由多个相互作用的模块构成，并且能够完成
  特定的功能。
n 使用增量模型时，第一个增量构件往往实现软件的基
  本需求，提供最核心的功能。
增量模型(渐增模型)
 增量模型(渐增模型)的优点

n 增量模型的优点：
 n 适用于人员配备不充裕、不能在软件项目期限之前实现一个完全
   版本的软件的情况；
 n 能有计划地管理技术风险；
 n 每个增量都发布了一个可操作的版本，用户能在较短时间内使用
   上部分功能；
 n 逐步增加产品功能可以使用户有较充裕的时间学习和适应新产品，
   减少一个全新的软件可能给客户带来的冲击。
增量模型(渐增模型)的难点


n 增量模型存在的困难：
 n 软件体系结构必须是开放的，使得每个新的增量构件能够
   无缝地集成到现有的软件体系结构中，增加了设计阶段的
   投入；
 n 本身具有矛盾性，一方面要求开发人员把软件看作一个整
   体，另一方面要求开发人员把软件看作构件序列，且构件
   间彼此独立。需要开发人员协调这一矛盾。

螺旋模型


n 软件项目中的风险：
 n 人员
 n 硬件设备

 n 项目的生存能力等

n 螺旋模型的基本思想：使用原型及其他方法来尽量降低风
  险。
n 可以把螺旋模型看作在每个阶段之前都增加了风险分析过
  程的快速原型模型。
螺旋模型
     螺旋模型

螺旋模型沿着螺线旋转，在
四个象限上分别表达四个任
务区域，即：
n制定计划──确定软件目标，

选定实施方案，弄清项目开
发的限制；
风险分析──分析所选方案，
n

考虑如何识别和消除风险；
n   实施工程──实施软件开发；
客户评估──评价开发工作，
n

提出修正建议，并计划下一
个阶段的任务；
螺旋模型的优点


n 螺旋模型是对瀑布模型的发展，并由客户对阶段性产
  品做出评审，这对保证软件产品质量十分有利；
n 由于引入风险分析等活动，测试活动的确定性增强了；

n 螺旋模型最外层代表维护，开发与维护采用同样方式，
  使维护得到与开发同样的重视。
螺旋模型的缺点

n 主要适合内部开发，否则风险分析必须在签订合同前
  完成，或者争取客户的最大理解；
n 只适合大型软件项目的开发，否则，每个阶段的风险
  分析将占用很大一部分资源，增加成本；
n 对开发人员的风险分析能力是极大的考验，否则，模
  型将退化到瀑布模型，甚至更糟。
