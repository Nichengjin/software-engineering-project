风险管理
什么是风险


n 风险：能造成恶果的有害事件

 u   不确定性：风险可能发生，也可能不发生；
 u   损失：风险如果变成现实，会带来损失；
 u   风险是尚未发生的问题，问题是业已成真的风险。
n 风险“具现”：风险变成问题的时候，也是风险转化的时刻。
风险为什么重要？


n 风险＝机会、机遇

n 风险和收益总是结伴而行。全无风险的项目也几乎全无收益；

n 清楚地知道坏事有可能发生、并做好相应的准备，是成熟的标
 志之一；
n 复杂开发项目中一定有不确定性，而哪里有不确定性，哪里就
 有风险。
 风险管理的策略


n 被动策略：针对可能发生的风险监督项目，直到它们变成真正的
问题时，才拨出资源来处理它们。
 u   “救火模式”

n 主动策略：标识出潜在的风险，评估它们出现的概率及产生的影
响，且按重要性加以排序，然后建立计划以管理风险。由于并不
是所有的风险都能预见到，所以项目组必须建立一个应急计划，
使其在必要时能够以可控及有效的方式做出反应。

风险识别——风险的类型

  n 项目风险：威胁项目计划

  n 技术风险：威胁所开发软件的质量及交付时间

  n 商业风险：威胁所开发软件的生存能力
   u   市场风险：没有人需要的产品
   u   策略风险：公司不打算支持的产品
   u   销售风险：销售性差的产品
   u   管理风险：建造中缺乏“关爱”的产品
   u   预算风险：没有得到预算或人力上的保证的产品
软件项目的核心风险

 n 进度安排的先天错误
  u   安排时间和工作量时犯下的错误。对规模的判断失误、预算的
      彻底失败。
 n 需求膨胀
  u   在开发的过程当中，客户的业务领域不可能始终静止不变；
  u   从项目的角度来看，需求总是向着膨胀的方向变化；
  u   合理的开发逻辑应该考虑到需求变化的可能程度而在制定的计
      划中允许一定限度的改变。
软件项目的核心风险


n 人员的流失
 u   需要掌握技术人员的年平均流动率，以及新人工作能“上手”的最短
     时间，从而为项目分配一定的缓冲人力资源；
n 规约崩溃
 u   问题的本质是在项目启动阶段商谈需求范围时没有谈拢；
 u   实际中有可能掩盖严重的冲突而定下一个让每一方勉强接受的含混不
     清的目标而开始项目；
 u   直到项目明确满足规约要求时此风险才消失。
风险分析——风险估算

n 风险影响（Risk   Impact）
 u 风险具现后所能造成的损失
 u 灾难性的、严重的、可以容忍的、可以忽略的


n 风险概率（Risk
          Probability）
n 风险概率的估算：
 u 历史数据
 u 可能性范围的确定：非常小(<10%)、小(10%~25%)、中等(25%~50%)、大

   (50%~75%)、非常大(>75%)
n 风险暴露值（Risk    Exposure）
 u   风险暴露值＝风险概率×风险影响
风险规划

n 根据风险分析的结果对风险进行优先级排列；

 u   参见《Top10风险列表》
n 针对风险优先级列表中的每种风险制定相应的管理对策，
要指定具体的风险负责人，指出风险具现的触发事件或临
界时间，制定该项风险的监控计划，并确定应对办法；
 u   参见《风险管理计划示例》
风险规划


n 风险规避（Risk   Avoidance）
 u   完全回避风险，排除造成风险事件的原因，或变更项目计划以保
     护项目目标免受风险事件的影响。
 u   建立风险缓解计划。
n 风险管理及应急计划

 u   假设缓解工作已经失败并且风险变成了现实。
风险监控



n 随着项目的进展，风险监控活动就开始了。

n 管理者对每一个识别的风险定期进行评估，从而确定风险
出现的可能性是变大还是变小、风险的影响后果是否有所
改变。
n 风险监控是个持续不断的过程。
