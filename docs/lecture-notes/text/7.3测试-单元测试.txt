单元测试
主讲人：冯 铁
测试重点

1. 模块接口：
 n 参数的数目、次序、属性或单位系统与变元是否一致；

 n 是否修改了只作输入用的变元；

 n 全局变量的定义和用法在各个模块中是否一致。

2. 局部数据结构：发现局部数据说明、初始化、默认值等方面的错误。
3. 重要的执行通路：选择最有代表性、最可能发现错误的执行通路进
   行测试。
测试重点
4. 出错处理通路：
 n 对错误的描述是难以理解的；

 n 记下的错误与实际遇到的错误不同；

 n 在对错误进行处理之前，错误条件已经引起系统干预；

 n 对错误的处理不正确；

 n 描述错误的信息不足以帮助确定造成错误的位置。

5. 边界条件:
 n 软件常常在它的边界上失效 。

 n 使用刚好小于、刚好等于和刚好大于最大值或最小值的数据结构、

   控制量和数据值的测试方案，非常可能发现软件中的错误。
代码审查

n 代码审查：可以查出30%到70%的逻辑设计错误和编码错误

n 审查小组的组成
 n 组长

 n 程序的设计者

 n 程序的编写者

 n 程序的测试者
代码审查

n 由审查小组对源程序正式进行人工测试。
 n 审查之前，小组成员应该先研究设计说明书，力求理解这个设计。
 n 审查会上倾听程序编写者的解释，并力图发现其中的错误。

 n 对照程序设计常见错误清单，分析审查这个程序。

n 预排：由一个人扮演“测试者”，其他人扮演“计算机”。

n 代码审查的优越性：一次审查会上可以发现许多错误，减少
系统验证的总工作量
计算机测试


n 需要编写驱动程序（driver）和存根程序（stub）。

n 驱动程序也就是一个“主程序”：接收测试数据，把这些数
  据传送给被测试的模块，印出有关结果。
n 存根程序代替被测试模块所调用的模块，也可以称为“虚拟
  子程序”和“桩模块”：做最少量的数据操作，印出对入口
  的检验或操作结果，把控制归还给调用它的模块。

计算机测试

n 编写驱动程序和存根程序是软件测试活动中不可避免
的一种工作开销。
n 可以采用渐增式测试方法，在集成测试的过程中同时
  完成对单一模块的详尽测试。
n 模块内聚度高可以简化单元测试过程。
