面向数据流的设计方法
n 通常所说的结构化设计方法（简称SD方法），也
就是面向数据流的设计方法。
n 面向数据流的设计方法把信息流映射成软件结构，
  信息流的类型决定了映射的方法。
n 信息流可以分为变换流和事务流。
面向数据流的设计方法
n 面向数据流的设计方法的基本过程：

 n 研究、分析和审查数据流图；

 n 根据数据流图决定问题的类型；

 n 由数据流图推导出系统的初始结构图；

 n 根据启发规则对结构进行细化；

 n 修改和补充数据字典；

 n 制定测试计划。

n 变换流：信息沿输入通路进入系统，同时由外部形式变
 换成内部形式，进入系统的信息通过变换中心，经加工
 处理以后再沿输出通路变换成外部形式离开软件系统。
 当数据流图具有这些特征时，这种信息流就叫作变换流。
面向数据流的设计方法
 n 变换型数据处理问题的工作过程大致分为三步，即
  取得数据，变换数据和给出数据。




 n 相应于取得数据、变换数据、给出数据，变换型系
  统结构图由输入、变换中心和输出等三部分组成。

n 事务流：数据沿输入通路到达一
 个处理 T ，这个处理根据输入数
 据的类型在若干个动作序列中选
 出一个来执行。这类信息流被称
 为事务流，而该处理 T 称为事务
 中心，它完成下述任务：
 n 接收输入数据(输入数据又称为事
   务transaction)；
 n 分析每个事务以确定它的类型；

 n 根据事务类型选取一条活动通路。

定的模式映射成软件结构的一系列步骤的总称。

n 第1步 复查基本系统模型
 n 复查的目的是确保系统的输入数据和输出数据符合实际。

n 第5步 完成“第一级分解(first level factoring)”。
  n 分解就是分配控制的过程。

  n 分解出模块：Cm,Ca,Ct,Ce，其中：

  n Cm：协调下述从属的控制功能；

  n Ca：输入信息处理控制模块，协调对所有输入数据的接收；

  n Ct：变换中心控制模块，管理对内部形式的数据的所有操作；

  n Ce：输出信息处理控制模块，协调输出信息的产生过程。

n 第6步 完成“第二级分解”

 n 把数据流图中的每个处理映射成软件结构中一个适当的模块。

  n 从变换中心的边界开始沿着输入通路向外移动，把输入通路中每
   个处理映射成软件结构中Ca控制下的一个低层模块；
  n 沿输出通路向外移动，把输出通路中每个处理映射成直接或间接
   受模块Ce控制的一个低层模块；
  n 把变换中心内的每个处理映射成受Ct控制的一个模块。

 n 为每个模块写一个简要说明：

  n 进出该模块的信息（接口描述）；

  n 模块内部的信息；

  n 过程陈述，包括主要判定点及任务等；

  n 对约束和特殊特点的简短讨论。

变换分析
n 第7步 使用设计原理和启发式规则对第一次分割得到的软
件结构进一步精化
 n 第一次分割得到的软件结构，总可以根据模块独立原理进行精
 化。
 n 为获得尽可能高的内聚、尽可能松散的耦合，应该对初步分割
 得到的模块进行再分解或合并。
变换分析
n 上述7个步骤的目的是：开发出软件的整体表示。这种整
体表示的意义在于：
 n 一旦确定了软件结构就可以把它作为一个整体来复查，从而能
 够评价和精化软件结构；
 n 在这个时期进行修改只需要很少的附加工作，但却能够对软件
 的质量特别是软件的可维护性产生深远的影响。
    变换分析实例
n   考虑汽车数字仪表板的设计。假设的仪表板将完成下述功能：
(1) 通过模数转换实现传感器和微处理机接口；
(2) 在发光二极管面板上显示数据；
(3) 指示每小时英里数(mph)，行驶的里程，每加仑油行驶的英里数
   (mpg)等等；
(4) 指示加速或减速；
(5) 超速警告：如果车速超过55英里/小时，则发出超速警告铃声。
