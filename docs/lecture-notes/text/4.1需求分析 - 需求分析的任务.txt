什么是需求

n   需求：就是系统的特征，或对系统为达到某个目标所
    能做的事情的一个描述。
n   需求：是对问题信息和系统行为、特性、设计及制造
    约束的描述的集合。
n   需求过程本质：在问题空间与求解空间中间架设桥梁。

项目干系人需求、系统需求

n   需求可能首先从项目干系人角度表达为一个非形式化
    的、不详细的、高层的描述，称为项目干系人需求
    （客户需求）；

n   然后从开发者角度出发，发展成更详细的形式，即系
    统需求。




                              15
    功能需求、非功能需求

n   功能需求：系统与环境间的交互——描述系统必须支持的
    功能和过程的系统需求。
n   非功能需求：客户给出的具体约束、指标——描述操作环
    境和性能目标的系统需求。
n   二者的区别：功能需求描述系统应该做什么，非功能需求
    则为如何实现这些需求设定约束。

    需求的特征

n   正确性：要确保需求的表达中没有引入错误（faults）。
n   一致性：确保没有互相冲突、矛盾的需求；确保没有不确定
    的需求。
n   完整性：如果需求描述了所有可能的状态，以及状态的变化、
    输入、过程和约束，那么这组需求就是完整的。




                               19
    需求的特征

n   现实性：确保客户要求系统做的事真的能做到。
n   实用性：确保需求和要解决的问题有直接关系。
n   可检验性：必须能写出测试来说明需求已被满足。
n   可回溯性：保证每个系统功能都能追溯到一组要求它的需求；
    确保很容易找到处理系统特定方面的某一组需求。

    需求文档
n   需求文档的可能使用者：
    u   系统客户：需要阅读需求文档来检验是否表达了他们的需要；
    u   软件项目管理者：需求文档是制定项目计划的基础之一；
    u   系统工程师：需要理解待开发系统；
    u   系统测试工程师：要依据需求文档制作测试用例，验证开发出
        的系统是否满足要求；
    u   系统维护人员：使用需求文档理解初始系统的特性和系统不同
        部分之间的关系。


                                      21
    需求文档
n   对应两种不同详细程度的需求（项目干系人需求、系统需
    求），有两种需求文档：
    u   需求定义（需求描述）
        • 用应用域术语编写
        • 彻底列举客户/用户想要系统做些什么
        • 由客户/用户和开发人员共同编写
    u   需求规约（软件需求规格说明，Software Requirements
        Specification）
        • 用开发人员擅长的技术术语编写
        • 需求定义的技术性版本，方便设计人员理解
        • 由分析人员编写

 需求分析的任务

n 必须理解并描述问题的信息域，根据这条准则应该建立数
  据模型；
n 必须定义软件应完成的功能，这条准则要求建立功能模型；

n 必须描述作为外部事件结果的软件行为，这条准则要求建
立行为模型；
n 必须对描述信息、功能和行为的模型进行分解，用层次的
方式展示细节
