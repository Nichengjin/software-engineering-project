什么是面向对象
n   Coad和Yourdon给出了一个定义：
    “面向对象=对象+类+继承+通过消息进行通信”   ★
    n 认为客观世界是由各种对象组成的，任何事物都是对象，
     复杂的对象可以由比较简单的对象以某种方式组合而成；
    n 把所有对象都划分成各种对象类（简称为类，class），
     每个对象类都定义了一组数据和一组方法；
    n 按照子类（或称为派生类）与父类（或称为基类）的关
     系，把若干个对象类组成一个层次结构的系统（也称为
     类等级）；
    n 对象彼此之间仅能通过传递消息互相联系。

面向对象的概念
n 对象：在应用领域中有意义的、与所要
 解决的问题有关系的任何事物都可以作
 为对象，它既可以是具体的物理实体的
 抽象，也可以是人为的概念，或者是任
 何有明确边界和意义的东西。
n 对象是由描述该对象属性的数据以及可
 以对这些数据施加的所有操作封装在一
 起构成的统一体。

面向对象的概念
n 对象的定义：
 n 定义1：对象是具有相同状态的一组操作的
   集合。
 n 定义2：对象是对问题域中某个东西的抽象，
   这种抽象反映了系统保存有关这个东西的信
   息或与它交互的能力。也就是说，对象是对
   属性值和操作的封装。
 n 定义3：对象∷=(ID，MS，DS，MI)。其中，
   ID是对象的标识或名字，MS是对象中的操
   作集合，DS是对象的数据结构，MI是对象
   受理的消息名集合(即对外接口)。

面向对象的概念

n 标识身份：意指数据与操作都被组织到
 相互分离、区别开来的问题空间实体当
 中。没有身份，对象就没有和某问题空

 丧失了与问题求解相关的语义，无法与
 其他问题空间对象相联系，也无法被集
 成进整个开发求解过程。

面向对象的概念

n 分类：把具有相同属性类型和操作的对象组成
 一组。
 n 分类本身具有主观性；

 n 要针对待解问题与其解决方案来确定如何分类；

 n 是组织问题空间知识的一种方法；

 n 类（class）：“类”就是对具有相同数据和相同操

 n 实例（instance）：实例就是由某个特定的类所描
  述的一个具体的对象。

面向对象的概念

n 封装：类封装了它的实例对象的属性与行为，
 隐藏实现细节。
n 对象具有封装性的条件如下：
 n 有一个清晰的边界。所有私有数据和实现操作的代
  码都被封装在这个边界内，从外面看不见更不能直
  接访问。
 n 有确定的接口（即协议）。这些接口就是对象可以
  接受的消息，只能通过向对象发送消息来使用它。
 n 受保护的内部实现。

n 或者反方向来看，是从“特殊性”概念归纳
 “一般性” 概念的一种机制。

面向对象方法学的优点
n 与人类习惯的思维方法一致：

 n 传统的程序设计技术忽略了数据和操作之间
  的内在联系，用这种方法所设计出来的软件
  系统其解空间与问题空间并不一致，难于理
  解。
 n 面向对象的软件技术以对象（object）为核
  心 , 而对象是数据和操作的统一体，是对现
  实世界实体的正确抽象。
 n 面向对象的设计方法与传统的面向过程的方
  法有本质不同：
                            19
面向对象方法学的优点
  n 面向对象的环境提供了强有力的抽象机制，便于
   用户在利用计算机软件系统解决复杂问题时使用
   习惯的抽象思维工具；
  n 面向对象方法学中普遍进行的对象分类过程，支
   持从特殊到一般的归纳思维过程；
  n 面向对象方法学中通过建立类等级而获得的继承
   特性，支持从一般到特殊的演绎思维过程；
  n 先设计出由抽象类构成的系统框架，随着认识深
   入和具体化再逐步派生出更具体的派生类——符
   合人们认识客观世界解决复杂问题时逐步深化的
   渐进过程。

                            20
面向对象方法学的优点
n 稳定性好：

 n 传统的软件开发方法以算法为核心，建立起
  来的软件系统的结构紧密依赖于系统所要完
  成的功能，当功能需求发生变化时将引起软
  件结构的整体修改。
 n 面向对象方法基于构造问题领域的对象模型，
  以对象为中心构造软件系统。由于现实世界
  中的实体是相对稳定的，因此，以对象为中
  心构造的软件系统也是比较稳定的。


                         21
面向对象方法学的优点
n 可重用性好：
 n 传统的软件重用技术是利用标准函数库，但是，标
  准函数缺乏必要的“柔性”。
 n 即使是具有功能内聚性的模块也并不是自含的和独
  立的，相反，它必须运行在相应的数据结构上。
 n 面向对象方法所使用的对象是数据和操作的统一体，
  因此，对象具有很强的自含性。对象固有的封装性
  和信息隐藏机制，使得对象的内部实现与外界隔离，
  具有较强的独立性。
 n 面向对象的软件技术在利用可重用的软件成分构造
  新的软件系统时，有很大的灵活性：实例化、继承。

                            22
面向对象方法学的优点
n 较易开发大型软件产品：

 n 面向对象范型中构成软件系统的每个对象就
  像一个微型程序，可以把一个大型软件产品
  分解成一系列本质上相互独立的小产品来处
  理。

面向对象方法学的优点
n 可维护性好：

 n 面向对象的软件稳定性比较好。

 n 面向对象的软件比较容易修改：封装，继承
  和多态性。
 n 面向对象的软件比较容易理解。

 n 易于测试和调试。

高级类建模——抽象类
n   抽象类（abstract class）：是指没有直接的实例的类，但其
    子孙类有直接的实例。
n   具体类（concrete class）：是指可以实例化的类，可以有直
    接的实例。
n   在UML中，抽象类名用斜体表示，也可以在名称下面或后

高级交互建模——用例关系
n   用例关系的准则：不要过度使用用例关系，更不要将用例
    关系用到编程当中。用例的目标是澄清需求。
    n   用例泛化：如果一个用例有几种变体，那么就用抽象用例
        建模公共的行为，再特化每种变体。
    n   用例包含：如果一项用例包含有一段定义良好且有可能用
        在其他场合的行为片段，那么就该为该行为定义一项用例，
        并把该用例包含在原始用例中。
    n   用例扩展：如果用可选特性来定义一项有意义的用例，那
        么要把基行为建模为用例，并用扩展关系来增加特性。
    n   包含关系和扩展关系：都可以把行为分解成较小的片段。
        但是，包含关系隐含着被包含行为是配置系统的一个必要
        的部分，而扩展关系暗示着没有增加的行为的系统也是有
        意义的。

活动模型

n 活动图（ activity   diagram ）显示了组成复杂过程
 的步骤序列。
n 与顺序图类似，活动图可以显示控制流，但专注
 于操作而不是对象。
n 活动图在设计算法和工作流的早期阶段最为有用；

n 类似流程图，描述一个Use Case的处理流程；

n 活动图可以方便地描述控制转移条件以及并行执
 行等要求。
