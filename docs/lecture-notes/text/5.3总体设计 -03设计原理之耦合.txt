主讲人：冯 铁
模块独立性：耦合（Coupling）

n 耦合是对一个软件结构内不同模块之间互连程度的度量。
  耦合强弱取决于模块间接口的复杂程度，进入或访问一
  个模块的点，以及通过接口的数据。
n 在软件设计中应该追求尽可能松散耦合的系统。

n 模块间的耦合程度强烈影响系统的可理解性、可测试性、
可靠性和可维护性。
模块独立性：耦合

n 耦合是模块与其他模块、外界之间连接程度的量化指标，模块
间联系越紧密、越多，耦合度就越高，模块的独立性就越差。

 是控制参数、公共数据结构或外部变量)来交换输入、输出信息的

n 标记耦合（Stamp Coupling）：能否化为数据耦合？

n 一组模块通过参数表传递记录信息，就是标记耦合。这个记录是某一
 数据结构，而不是简单变量
n 标记耦合使在数据结构上的操作复杂化了，把在数据结构上的操作全
 部集中在一个模块中，可消除或转化这种耦合

n 控制耦合（Control Coupling）：中等耦合度


• 如果一个模块通过传送开关、标志、名
字等控制信息，明显地控制选择另一模块
的功能，就是控制耦合
• 这种耦合实质是在单一接口上选择多功
能模块中的某项功能，如右图。因此对模
块B的任何改动都会影响模块A
• 控制耦合意味着A必须知道B内部的一些
逻辑关系，这会降低模块的独立性
n 外部耦合（External Coupling）：若不可避免，尽量集中

n 一组模块都访问同一全局简单变量而不是同一全局数据结构，而
  且不是通过参数表传递该全局变量的信息，则称之为外部耦合
n 例如C语言程序中有模块访问被修饰为extern的外部变量

n 外部耦合会引起下列问题：
 n 无法控制各模块对公共数据的存取，严重影响软件模块的可靠性和适应性
 n 公共数据名的使用，明显降低了程序的可读性
n 公共耦合（Common Coupling）：危险，慎用

n 若一组模块都访问同一个公共数据环境，则它们之间的耦合就称
  为公共耦合。公共的数据环境可以是全局数据结构、共享的通信
  区、内存的公共覆盖区等。
n 例如： FORTRAN 语言中的 COMMON 区可以使访问它的模块间发生
  公共耦合
n 这种耦合会引起下列问题：
 n 所有公共耦合模块都与某个公共数据环境内部各项的物理安排有关，若修
   改某个数据的大小，将会影响到所有模块
 n 无法控制各模块对公共数据的存取，严重影响软件模块的可靠性和适应性

 n 公共数据名的使用，明显降低了程序的可读性

n 内容耦合（Content Coupling）：耦合度最高，现代高级语言基
 本上不允许出现内容耦合
n 如果发生下列情形，两个模块之间就发生了内容耦合
 n 一个模块直接访问另一个模块的内部数据

 n 一个模块不通过正常入口转到另一模块内部
 n 两个模块有一部分程序代码重迭(只可能出现在汇编语言中)

 n 一个模块有多个入口
n 针对耦合的设计指导原则：
 n 尽量使用数据耦合
 n 少用控制耦合和特征耦合

 n 限制外部耦合和公共耦合

 n 完全不用内容耦合

n 降低耦合度的方法：
 n 根据问题的特点，选择适当的耦合类型；(控制耦合?出错处理?)

 n 降低模块接口的复杂性；(信息数量/联系方式/信息结构)

 n 把模块的通信信息放在缓冲区中；

 n 减少公共区，使之局部化。可以把公共区划分为若干个逻辑子区；

 n 输入输出应局限在少数模块，不要分散在全系统。
