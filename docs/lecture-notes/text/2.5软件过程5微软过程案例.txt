背景介绍
n 1995年微软推出IE1.0版本，Netscape公司向外界宣称:“我们领
  先微软二年，他们永远也别想追上我们”。
n 1996年，发布了IE2.0版本，Netscape公司:“我们领先微软一年
  ，他们永远也别想追上我们。”
n 1996年末，IE3.0版问世。美国最大的Internet服务商——美国在
  线(AOL)最终决定使用IE 3.0作为其预设的浏览器软件。
n 1997 年 ， 新 推 出 的 IE4.0 几 乎 在 所 有 媒 体 评 测 中 都 击 败 了
  Netscape 的 产 品 。 1998 年 11 月 ， 美 国 在 线 (AOL) 宣 布 收 购
  Netscape公司。
n 1999年，IE5.0向全球用户展示了卓越的运行效率和稳定性。市
  场上已经没有多少人对Netscape念念不忘了。
n 2001年，IE6.0面世。占据了93%~94%的市场份额，而Netscape
  的市场份额则下降到了3.5%，浏览器市场之争到此已经硝烟散
  尽。                                                3

项目方法
n 构想阶段：
 n 微软公司之所以能在浏览器之争中胜出，其构想阶
   段中成功的市场需求分析是关键因素之一。
 n (1)关注关键需求：
   n 只应该关注那些用户最常使用的、市场最需要的关键特
    性需求
 n (2)仔细研究竞争对手

 n (3)关注 Internet 新用户：
   n 在研究用户需求时，更注意为那些刚刚接触Internet、没
    有太多上网浏览经验的用户考虑。微软公司在
    IE3.0~IE6.0各个版本中都为新用户特别设计了许多简单
    易用的功能。

项目方法
n 计划阶段
 n 编写单页功能说明书
 n 单页功能说明书由程序经理编写，在IE的某一个版本中，需
   要开发100个产品特性，则程序经理需要编写100份单页功能
   说明书，对于50个程序经理，每个程序经理负责2~3个产品
   特性。
 n 目的是让开发工程师、测试工程师和其他项目组成员清楚每
   项产品特性的功能、操作方式和接口等信息，了解为什么需
   要这些产品特性(客户的直接需要还是市场竞争的需要)。此
   外，单页功能说明书还必须明确各产品特性的优先级。产品
   特性的优先级主要依据市场需要的紧迫程度和该特性在产品
   构架中的地位等因素确定。在安排具体的开发任务时，可以
   依据产品特性的优先级关系安排开发顺序；当资源或时间有
   限时，也可以放弃某些优先级低的产品特性。       10

项目方法
n 发布阶段
 n 使用各种发布渠道向用户免费发放IE浏览器

  n 微软公司不向客户收取使用IE浏览器的任何费用。更为重
      要的是，IE浏览器不仅对个人用户是免费的，对所有企业
      用户也是免费的。这一销售策略帮助微软公司在最短的时
      间内扭转了市场颓势，赢得了最广泛的用户支持。
 n 细分客户群

    n 微软公司在发布IE时，不仅对个人用户提供足够的支持，
      也对企业用户、包括大型企业用户提供完善的服务。这种
      全面、细致的营销和服务体系帮助微软赢得了大多数客户
      的信任和支持。

IE项目四要素间的关系
n 在进度(即过程的进度时间)一定的情况下，可
以选择产品的功能和性能，并对资源(包括人
员、方法等)做必要的调整。
 n “进度一定”是指微软在每个IE版本发布新功能
  时应总是比Netscape抢先一步；
 n “可以选择的产品功能与性能”是指为每个版本
  选择关键特性，并且每个版本之间持续、递进地
  交付；
 n “对资源做必要的调整”是指，如人员的配备在
  IE1.0时为7人，到 IE5.0时猛增至500人。
