集成测试

n 集成测试是测试和组装软件的系统化技术。

 n 非渐增式测试：先分别测试每个模块，再一次性把所
  有模块按设计要求集成到一起进行测试。
 n 渐增式测试：把下一个要测试的模块同已测试好的那
  些模块结合起来进行测试，依次类推，每次增加一个模
  块。这种方法实质上同时完成单元测试和集成测试。

集成测试
 集成测试：一次性集成
n 当所有组件都单独测试完毕之后，将它们一次性组成最终的
系统，查看其是否能够运行成功。
              n 缺点：
                n 需要编写大量存根程序和驱动
                  程序。
                n 所有组件一次进行合并，很难
                  找出所有错误的原因。
                n 不容易区分接口错误与其他类
                  型的错误。
集成测试：自顶向下集成


  n 从主控制模块开始，沿着程序的控制层次向下
  移动，逐渐把各个模块结合起来。
  n 在把附属于（及最终附属于）主控制模块的那
  些模块组装到程序结构中去时，或者使用深度
  优先的策略，或者使用宽度优先的策略。
集成测试：自顶向下集成
集成测试：自顶向下集成

 n 优点：
  n 自顶向下的集成策略能够在测试的早期对主要的控制或关键的抉择
    进行检验。
  n 自顶向下测试不需要驱动程序。

  n 选择深度优先的结合方法，可以在早期实现软件的一个完整的功能
   并且验证这个功能。
 n 缺点：
  n 需要编写存根程序。
  n 为了充分地测试软件系统的较高层次，需要在较低层次上的处理。

  n 可能需要很多存根程序。
集成测试：自底向上集成


 n 从“原子”模块(即在软件结构最低层的模块)开
 始组装和测试，不需要存根程序。
 n 当底层有许多组件是有多种用途的公用例程而经
 常被其他组件调用时、当设计是面向对象的或当
 系统由大量孤立的复用的组件组成时，自底向上
 方法是很有用的。
集成测试：自底向上集成
集成测试：自底向上集成

  n 优点：
   n 不需要编写存根程序。
   n 测试驱动程序的数目较少。

   n 底层模块往往承担主要的计算和输入、输出任务，更
     容易出错，该策略可以在早期发现这类错误。
   n 底层模块可以并行测试。

  n 缺点：
   n 对顶层组件测试进行得晚，推迟了对主要错误的发现。

   n 程序在最后一个模块加入时才具有整体形象。

回归测试

n 回归测试（regression test）是指重新执行已经做过的
 测试的某个子集，以保证由于调试或其他原因引起的
 变化不会导致非预期的软件行为或额外错误。
n 回归测试集（已执行过的测试用例的子集）包括下述3
 类不同的测试用例：
 n 检测软件全部功能的代表性测试用例；

 n 专门针对可能受修改影响的软件功能的附加测试；

 n 针对被修改过的软件成分的测试。
