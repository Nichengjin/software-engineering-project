## 3. 评审规则

- 每个 PR 至少由作者以外的一人评审，评审人见上表；评审意见留在 PR 中。
- 倪成锦的代码由相关模块负责人评审，避免同一人独自实现并批准。
- 冯海伦核对每条 AC 的验收证据；涉及共享接口和数据结构的变更由倪成锦协调，涉及架构的写 ADR。

## 4. 提交作者与时间

团队在一台电脑上集中提交。git 历史是课程评分的过程证据，也是贡献百分比的依据，因此：

- 作者是实际完成这项工作的成员：`git commit --author="姓名 <邮箱>"`。两人合作的提交在末尾加 `Co-authored-by: 姓名 <邮箱>`。
- 作者时间默认为提交时刻。线下完成、稍后集中提交时，可将 `GIT_AUTHOR_DATE` 设为实际完成时间，并在正文注明“线下完成，集中提交”。
- 不以本表的分配或计划日期代替实际作者和时间。工作由他人完成时，作者写实际完成的人，分工偏离记入迭代回顾。
- 不改写已有提交的作者或时间。进度延误在迭代评审中说明。
- 借助 AI 工具完成的工作，作者为发起并审核该工作的成员，提交信息保留 AI 协作署名。
