# AC-01 至 AC-64 独立验收场景矩阵

- 输入：[需求分析 v0.6](../REQUIREMENTS_ANALYSIS.md)、[OOA v0.3](../design-docs/object-oriented-analysis.md)；环境、数据别名及责任见 [测试计划](../TEST_PLAN.md)。关联 US-018，具体业务 US 逐行列出。
- 全部初始状态为 **未执行**；实际结果、执行者、时间、候选提交、证据及缺陷号均待实际执行填写。本文不是冯海伦的验收签字或测试报告。
- “界面＋接口”要求冯海伦走页面并用真实身份直接请求可信执行端；“集成”要求同时观察持久化业务数据；“故障／并发”要求可控屏障或注入，不以正常串行请求代替。开发者可按相同设计自测，但自测结果不能自动填成独立验收通过。
- 每行多个条件分开复位、执行、记录；所有子场景完成后才能判整行通过。默认 T2 在选课窗口内、账户已改密、目录正常、目标班次有本地教授、先修满足、名额足够；覆盖例外时按行覆盖默认条件。
- 失败比较业务快照（课表保存／成功提交版本、首次时间、有效注册、名册、人数、授课、成绩、人员、关闭及计费版本），允许增加失败审计，不允许部分业务修改。查询只读；逐格成绩和逐行导入按各自明确例外处理。
- 预期由手写成员集合、排序表及学分计算确定；不调用生产代码得到预期。没有真实业务实现或测试控制能力时维持未执行，进入执行轮后记阻塞并写缺失项。
