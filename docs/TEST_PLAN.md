- 输入：[需求分析 v0.6](REQUIREMENTS_ANALYSIS.md)、[OOA v0.3](design-docs/object-oriented-analysis.md)、[测试策略](TESTING.md)、[团队分工](TEAM_ROLES.md)。需求和分析本身仍待团队评审。

## 1. 验证责任与执行顺序

| 验证活动 | 责任与证据 | 不可替代的独立检查 |
| --- | --- | --- |
| 规则单元测试 | 模块开发者：数量、先修、冲突、排序、金额；提交测试命令、版本及输出 | 冯海伦按矩阵另选非对称数据，预期来自需求与手算，不调用生产规则生成期望值 |
| 数据库与外部接口集成 | 倪成锦及各模块开发者；范昭提供目录、计费模拟与故障开关 | 冯海伦直接比较课表、名册、人数、持久化待发资料与模拟账单；不能只看 HTTP 成功或日志 |
| 页面、权限、并发与故障验收 | 冯海伦独立执行；负责人修复缺陷并提供自测 | 真实登录身份、两会话竞争、服务重启、目录事件与审计核对，保留实际证据 |
| 性能、兼容、长期可用性 | 冯海伦执行，范昭记录环境，倪成锦分析差距 | 必须有实测，不能由单元测试、Linux 浏览器或短时演示推断达标 |
| 自动化门禁 | Agent／开发者运行 `make ci` | 目前包含文档／卫生／Actions检查、client生成、测试迁移、strict类型检查、全量Vitest及全部构建；不自动证明所有AC页面／NFR通过 |

按以下批次执行，每批先复位数据，不要求前一用例替后一用例建立状态：

1. 底座冒烟：初始化首个教务账户 → 导入人员和资格 → 时间设定 → 改密登录 → 目录浏览（AC-01 至 AC-04、AC-43、AC-56、AC-59 至 AC-61）。
2. 学生／教授业务：保存、提交、加退选、删除、授课、名册、成绩及人员状态；同步执行 AC-37 至 AC-44 的权限回归。
3. 高风险集成：AC-08、AC-28 至 AC-36、AC-45 至 AC-55、AC-63、AC-64，验证最后名额、旧版本、目录变更、关闭恢复和持久化计费。
4. 补选和全链路：AC-57、AC-58、AC-62，包括补选并发与旧计费版本晚到；从导入到出账再到上一已完成学期成绩查阅，核对各角色界面。
5. 另行安排 NFR 实测与独立环境启动；不得把“今晚业务开发结束”写成独立验收或课程交付完成。

## 2. 准入、退出与缺陷闭环

准入要求：固定候选提交；启动与初始化说明可用；React／Hono／PostgreSQL 及两套模拟正常；迁移只针对隔离测试库；账户、权限和目标学期可准备；开发者提供实际自测结果。缺少某个故障开关时该项记“阻塞”，不能改成简单正常请求后判通过。

退出要求：64 条 AC 的全部子场景有实际结果与证据；越权、重复收费、超容量、数据丢失、失败部分写入、主流程不可完成类缺陷全部关闭并独立复测；其他已知缺陷与未测 NFR 明示，由团队决定候选版本是否可接受。只有人工评审真实发生后才记录评审结论。NFR 未实测时功能验证可以单独结束，但不能宣称整体验收通过。

状态用“未执行／通过／失败／阻塞”，本计划与矩阵初始全部未执行。通过只适用于实际执行的候选版本和环境；同一 AC 有多个子场景时，缺一项不得整体通过。

每次执行记录至少包含：AC／子场景、提交与环境、执行者、Asia/Shanghai 时间、复位数据版本、步骤与请求、手写预期、实际 UI／响应／数据库／模拟账单结果、证据位置、缺陷号。不要在证据中保留密码、完整社会安全号码或真实个人信息。

缺陷由冯海伦登记复现输入和失败事实，按学生端浩宇、教授端马喆、教务端冯海洋、核心事务倪成锦、外部模拟范昭分派。开发者先补复现测试再修复；冯海伦在新提交复测原场景并回归关联 AC。开发者测试报告与独立验收记录分别标注执行者，不互相冒签。

## 3. 环境与可测试性要求

| 项目 | 必须准备的条件 | 负责配合 |
| --- | --- | --- |
| 启动与隔离 | 记录 OS、CPU／内存、Node／数据库版本、提交、启动方式及各进程；专用测试库可重建，禁止写共享或生产库 | 范昭、倪成锦 |
| 数据复位 | 可重复初始化三角色、状态、学期与班次；关闭和删除用例每次全新恢复；分别保留最近保存与最后提交的选择 | 各模块开发者、范昭 |
| 系统时间 | 注入业务时钟，控制确认点与重试调度，不只更改页面文案；记录时区与毫秒精度；不可因调时破坏认证测试 | 倪成锦、冯海洋 |
| 并发屏障 | 在写入确认前暂停／放行学生提交、教授争选及补选；明确“进入处理”与“完成确认”观察点，不能仅两次点击顺序调用 | 倪成锦 |
| 故障控制 | 目录空／失败／超时／改时间／加先修／删除；关闭第 3 步故障；计费不可用／接收后丢响应／乱序／恢复；均可复位 | 倪成锦、范昭 |
| 持久性核对 | 只读测试数据查询或导出，提供注册、课表版本、首次时间、关闭状态、待发版本、模拟账单、审计；期望不依赖产品内部计算函数 | 倪成锦、范昭 |
| 浏览器会话 | 两个不同学生、两教授及同学生双标签／会话；记录触发时刻到界面更新时间，离线与在线分开 | 冯海伦 |
| 安全隔离 | 测试控制接口只能用于测试环境，不能以学生请求字段切换角色或故障；虚构人员，初始密码运行时获取且不入文档 | 全体开发者 |

实现已合入主线。当前命令见 [测试策略](TESTING.md)：`npm run test:acceptance`、`npm run test:e2e`、`npm run test:load`。验收使用真实PG数据库、HTTP模拟、业务时钟、屏障与故障注入；进程重启测试启动并关闭有限API子进程，不启动开发服务器。实际版本、次数、结果、限制与复核结论统一写入测试报告。

矩阵用以下别名，不强迫实现采用这些主键。种子完成后记录别名到实际编号映射，人数通过真实有效注册构造，不能只写一个假人数字段。

## 6. 统筹已采纳的实施口径

2026-10-05，统筹依据用户“有不清楚的地方替我做决定”的授权采纳以下四项，已与 [总体设计](design-docs/system-design.md) 和 [API 契约](design-docs/api-contract.md) 核对一致。这是实施决定，不是团队评审或冯海伦验收。矩阵保留编写时的“推荐口径”标记以便追溯，执行时以这两份设计中的明确规则为准。

| 边界 | 推荐与理由 | 影响 |
| --- | --- | --- |
| 时间端点及提前关闭跨自然截止 | 用 Asia/Shanghai 解释业务时间，窗口左闭右开；18:00 恰好确认视为截止。提前关闭前已进入处理的请求免受“正在关闭”门禁，但仍须在自然截止前确认。Q-19 只解决提前关闭，不应使 AC-50 自然截止失效 | AC-28、AC-50、AC-56 的精确端点；开发者需定义可信进入处理点 |
| 已关闭后目录变更 | BR-14 明确“选课期间”，但未定义关闭后学分／时间／删除变动如何更正已出账。推荐关闭结果及计费冻结关闭时目录版本；补选按明确可追溯的班次信息计算新账单，不静默重算旧账。后续关闭后目录修改处理另作需求，不凭轮询删除已出账记录 | 目录缓存／快照、计费版本设计；本矩阵只验收选课期间变更 |
| 上一已完成学期如何准备 | “关闭选课”不能替代“学期已完成”。推荐初始化／测试准备显式指定已完成学期和上线学期，按时间取最近完成者；不增加未授权的学生或教务随意改成绩学期入口 | AC-19 至 AC-23、AC-60；成绩集成前需真实环境前置 |
| 同一个班次重复占条目 | 主选同课程禁止重复已明确，备选允许同课程不同班次，但未规定同班重复及同时列为主备。推荐同一班次在整份选择中只出现一次，避免两项重复消耗备选顺序或产生伪 4+2；允许同课程不同班次作为备选 | 数量与列表契约；新增校验须在需求中明确后再独立验收，不偷偷更改 AC-48 |

无需重新决定的规则：提前关闭在途提交计入；补选最多 4 门；删除清首次时间、重建 4+2；保存与提交都拒绝旧版本；最新计费版本替代旧版本且旧版本晚到不能覆盖。它们已在 v0.6／OOA v0.3 明确，测试不得再按相反解释编写。
