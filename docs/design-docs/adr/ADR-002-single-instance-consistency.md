# ADR-002：单 API 实例、持久化会话及事务 outbox

- 日期：2026-10-05；US-026／IT-02，US-027 落地。
- 状态：已选择供授权执行；团队设计评审未进行，不代表验收通过。
- 依据：用户授权今晚统筹自行收口设计和实现，沿用 ADR-001 技术栈；需求 v0.6／OOA v0.3 业务规则不变。

## 背景

需要前后端、底座和模拟系统快速独立实现 UC-01—14。容量竞争、关闭前在途提交、关闭失败回滚及计费丢响应不能靠页面提示解决。课程交付时间有限，无真实旧系统可接入，性能要求仍需实测。

## 决定

1. Node 22 LTS＋Hono 单进程，React／Vite SPA，npm workspaces、Prisma 6、PostgreSQL 15；目录为 apps/api、apps/web、apps/simulators、packages/db、packages/contracts。生产 Hono 同源托管 SPA，开发 Vite 代理；包小版本由底座锁定。
2. 数据库 opaque session cookie，HttpOnly／SameSite／Secure、同源＋CSRF、每请求角色／人员状态检查。初始凭据只在教务创建／导入响应一次性受限发放；不存明文或记日志。
3. 单进程 admission gate 区分提前关闭前后的新写请求；已准入 token 允许自然截止前确认的在途提交完成。人员锁→学期事务锁→记录锁的统一顺序保证原子更新和容量／教授竞争。为阻止误开第二 API，持有数据库 session-level leader lock；不支持多实例。
4. 关闭 drain 后调剂、取消、最终课表、学期 CLOSED 和每学生账单 outbox 同事务提交；内部失败恢复 OPEN，已完成在途提交保留。重启恢复 CLOSING 时只恢复意图，不自动重跑调剂；CLOSED 不回到 OPEN。
5. outbox 每 60 秒重试既有版本，HTTP 在事务外；外部按学生＋学期最高版本替换、按 businessId 去重，补选同事务生成更正版本。独立模拟 HTTP 服务独立文件持久化，不依赖业务库作为目录权威。
6. 目录／页面各 1 秒轮询，以真实测试验证在线 5 秒可见；`api-contract.md` 是 DTO／路径唯一入口，`system-design.md` 是字段与一致性入口，不按分析类逐一建实现层。

## 取舍与后果

- 不选择内存 session／内存待发队列，因为重启需要恢复登录与账单；不把外部 HTTP 放进长事务。
- 不选择多实例／Redis／通用消息队列，因为尚无环境与多实例验收证据，增加分布式关闭协调成本；未来需要多实例时另写 ADR。
- 串行写锁牺牲吞吐，须测原题 500／2000 同时用户及交易耗时；本决定不保证性能达标、24×7 可用或真实旧系统兼容。
- PostgreSQL 15 使用父线程已准备的真实测试环境；不能把父线程环境报告写成本工作区已执行 DB 测试。
- 接口与数据模型现在可指导实现，StarUML 视图布置和设计图导出后补；团队评审、独立验收、PR／发布仍是独立门禁。

## 验证条件

真实 DB 并发最后名额／教授争选；提前关闭新请求拒绝而在途成功；自然截止边界；关闭 fault rollback／进程重启；同事务 outbox；丢确认和新旧版本乱序；第二 API 实例拒绝启动；权限矩阵与 xlsx 逐行；两浏览器 5 秒刷新。具体输入见总体设计第 8 节，结果由实际执行记录提供，当前均未执行。
