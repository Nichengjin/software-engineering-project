# ADR-003：合并尚未开始的目录刷新轮次

- 日期：2026-10-07；US-018／IT-04；负责人倪成锦。
- 状态：用户授权的本地修复候选，未合入、未团队评审。
- 背景：[PERF-01及执行计划](../../exec-plans/active/2026-10-07-performance-fix.md)。逐写请求排一次目录HTTP与事务，导致同学期等待随请求数增长。

## 决定

每学期最多一轮刷新运行、一轮尚未开始；尚未开始的调用共享同一个Promise。HTTP开始后到达的新请求进入下一轮，不共享请求到达前已经发出的HTTP，也不采用TTL缓存。轮次包含HTTP读取及镜像应用，应用完成才发布结果，旧轮次不能晚到覆盖新轮次。

共享轮次的应用资格合并：任一已准入写或关闭协调器需要应用时，该轮允许在CLOSING期间应用；写请求各自持有原准入直到业务事务结束。只有后台调用的轮次仍检查gate，必要时自己取得并释放准入。该轮HTTP或应用失败拒绝全部参与者，后继轮次继续运行。

保留全局人员写锁＋学期锁、事务中目录revision复查、自然截止与关闭排空。不修改协议、数据模型或8秒外部／120秒客户端期限。目录投影用数据库有效注册计数，不读取完整注册明细；版本和观察时间查询只选择所需字段，选课校验仅查询主选／备选班次。

只读目录采用独立的同样下一轮合并规则，按学期＋教授标识隔离，下一轮HTTP和本地投影共享结果；不缓存已完成的轮次，不触发镜像应用，保留revision未同步时409。调用者显式提供快照时直接投影，不加入HTTP队列。第一、二轮短测说明只合并写刷新／缩小查询仍不足以承受大量完整目录并发读取，原始失败结果保留在报告中。

## 取舍与验证

简单single-flight会复用已开始的观察，不满足本项目新鲜度边界；逐请求串行满足顺序但积压无界。新轮次合并限制拉取次数，仍不保证写事务吞吐或2000用户容量；完整测量结果见测试报告。

屏障测试覆盖2000调用共用下一轮、运行中第三轮、跨学期、HTTP／应用失败恢复、后台与写／关闭资格组合、应用期间drain、只读共享与教授视角隔离。真实PG回归核对有效人数、远端顺序、教授和资格；原关闭、末席竞争、越权、目录变更及回滚测试保留。
