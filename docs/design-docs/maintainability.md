# 可维护性与后续维护

- 版本：v0.1，2026-10-09；关联 US-030／IT-04。
- 依据：课件 8.1—8.3；当前源代码、测试与运行说明。

## 1. 四个方面的现状

| 属性 | 已有措施 | 具体短板与维护动作 |
| --- | --- | --- |
| 可理解性 | 需求／用例／契约／schema 同仓库；模块职责、流程图、伪代码和数据字典可互相定位 | `app.ts` 仍含部分查询与业务组装；维护前读对应 AC，优先把复杂分支的原因写在函数附近 |
| 可测试性 | `createApplication` 不监听端口，可注入时钟、外部客户端和故障屏障；真实 PG 夹具自动清理 | 依赖真实数据库使集成测试较慢；前端浏览器分支未计入 V8 百分比，需针对高风险交互继续补测 |
| 可修改性 | 纯规则、外部 HTTP、业务服务、页面分开；严格 contracts、版本检查和不可变 outbox 守住边界 | 人员修改事务复杂度 31、课表事务 23、关闭事务 19。拆分时保持锁顺序、同事务审计和整体回滚；先用现有 AC 固定行为 |
| 可移植性 | Node、PostgreSQL、npm lock 与环境示例明确；生产构建不依赖开发服务器 | API 有单实例领导锁；浏览器脚本当前依赖 macOS Chrome 与 agent-browser；Windows／Edge、独立机器启动仍需实测 |

复杂度与覆盖率用于定位维护成本，不能独自衡量质量。测试不够充分时，低复杂度的租约／异步发送代码同样可能产生严重问题。

## 2. 维护分类与实例

| 类型 | 本项目实例／后续工作 | 处理方式 |
| --- | --- | --- |
| 改正性维护 | BUG-001 可辨认性与按钮截断修复 | 失败复现 → 修复 → 原用例和相关功能回归 → history 与追溯 |
| 完善性维护 | PERF-01 目录请求合并与查询缩小 | 保持规则与超时口径，短诊断后完整负载复测，保留原失败结果 |
| 适应性维护 | 将来接入真实目录／计费系统或新增目标 OS | 先核对契约、环境和数据迁移影响，再建立兼容性验收；目前尚未执行 |
| 预防性维护 | 分离高复杂度校验、补齐前端分支和依赖扫描 | 排入后续需求，不在收尾阶段顺手改变已冻结的业务范围 |

## 3. 修改与故障处理流程

1. 登记 BUG／用户故事，记录角色、学期、操作、实际结果和预期结果。
2. 按 [数据字典](data-dictionary.md) 和 [算法设计](algorithm-design.md) 确认数据与事务边界，补复现测试。
3. 在短分支修改；数据库变化用新迁移，不修改已经应用的旧迁移。
4. 跑相关用例、`make ci`；涉及页面、故障恢复或负载的，重跑对应验证。
5. 同步契约、设计、用户手册、history 和追溯，经仓库既有流程合入并形成发布记录。

初始化与故障操作见 [开发说明](../DEVELOPMENT.md)，发布与备份配置项见 [配置管理计划](../CONFIG_MANAGEMENT_PLAN.md)。已有数据的演示库不可通过重复 seed 恢复初始状态；需要重新演示时使用独立新库。关闭后不提供“重开选课”按钮，维护时不能手改状态来假装恢复。

本项目仍处于首次交付前，不开展旧系统再工程或 CMM 成熟度认证；现有工程措施可作为改进基础，不据此宣称达到某个成熟度等级。没有长期故障样本，暂不计算 MTTF；七天可用性按测试计划真实观察后记录。
